# 프로젝트3 실습 절차 — 결정사항 예시 (노원구 사례)

이 문서는 학습 자료(`웹지도_만들기.md`)의 실습 절차에서 비워 둔 "결정사항" 칸을, 노원구 프로젝트를 실제로 진행하며 내린 결정으로 채운 예시이다. 웹지도 제작(1차시), 인터랙션 구현 및 배포(2~3차시)의 두 단계로 나누어 정리한다.

---

## 1. 웹지도 제작 실행 절차 — 결정사항 예시 (1차시 관련)

| 순서 | 실행 내용 | 확인·결정할 사항 | 결정사항 (예시) |
|---|---|---|---|
| 1 | 웹지도 제작 대상 결정 | 어떤 프로젝트 결과물을 웹지도로 만들 것인지, 데이터 형태(포인트/폴리곤) | 프로젝트1(대피소 입지 적합성 분석) 결과 선택. 격자 단위 적합도 점수를 웹지도 대상으로 함 |
| 2 | 웹지도 표현 방식 결정 | QGIS2Web(자동 변환) vs AI 직접 코딩(Leaflet) 중 무엇을 먼저 시도할지 | 두 방식을 모두 진행해 비교하기로 결정. QGIS2Web을 먼저 시도해 빠르게 결과를 확인한 뒤, 동일 데이터로 AI 직접 코딩을 진행 |
| 3 | 팝업·색상 표현 필드 결정 | 웹지도에 표시할 핵심 필드 | `suitability`(적합도 점수) 필드만 팝업에 포함. 나머지 중간 계산 필드는 제외해 파일 용량 절감 |
| 4 | 좌표계 확인 | 웹지도는 EPSG:4326을 사용해야 함 — 현재 데이터 좌표계 확인 필요 | 기존 분석은 EPSG:5179(투영좌표계) 사용 중이었음을 확인. GeoJSON 내보내기 시 EPSG:4326으로 재투영 |
| 5 | AI 요청 프롬프트 구성 | 역할·맥락·요청·제약을 어떻게 구체화할지 | "Leaflet 전문 개발자" 역할 지정, `suitability` 필드 의미 설명, 색상 그라데이션(노랑→빨강)·팝업·단일 HTML 파일 등 요청 사항을 구체적으로 명시 |
| 6 | 결과 비교 방식 결정 | 두 결과물을 어떤 기준으로 비교할지 | 걸린 시간, 색상 표현, 범례, 팝업 내용, 코드 이해도, 커스터마이징 자유도, 재사용성 7개 항목으로 비교표 작성 |

> 노원구 웹지도 제작 과정에서 위 표의 "결정사항" 칸을 채운 흐름은 `웹지도만들기_AI와_실습절차_수행.md` 1절에서 확인할 수 있다.

---

## 2. 인터랙션 구현 및 배포 실행 절차 — 결정사항 예시 (2~3차시 관련)

| 순서 | 실행 내용 | 확인·결정할 사항 | 결정사항 (예시) |
|---|---|---|---|
| 1 | 추가할 인터랙션 기능 결정 | 어떤 필터·검색 기능이 유용할지 | 적합도 구간 슬라이더 채택 — 기준값 미만 포인트는 투명 처리하여 상위 후보지만 강조 |
| 2 | 수정 요청 방식 결정 | 전체 재작성 요청 vs 부분 수정 요청 | 기존 코드 전체를 맥락으로 제공하고, "기존 코드 구조(getColor, fitBounds 등)는 유지"라는 제약을 명시한 부분 수정 프롬프트 사용 |
| 3 | 배포 플랫폼 결정 | GitHub Pages vs 기타 정적 호스팅 | GitHub Pages 채택 — 무료이며 정적 파일(HTML) 배포에 적합, Public 저장소로 진행 |
| 4 | 업로드 파일 범위 결정 | 웹지도 HTML만 게시할지, 원본 데이터도 함께 게시할지 | 정제된 웹지도 HTML(`suitability`만 남긴 버전)만 게시. 원본 GeoJSON·CSV(관리번호·시설위치·수용인원 등 민감 필드 포함본)는 비공개로 유지 |
| 5 | 반응형·사용성 검증 방법 결정 | 어떤 기기로, 어떤 과업으로 테스트할지 | 스마트폰 브라우저로 반응형(화면 크기, 슬라이더 잘림, 확대·축소) 확인. "적합도가 가장 높은 지역 3곳 찾기" 과업으로 동료 대상 사용성 테스트 진행 |

> 노원구 웹지도 배포 과정에서 위 표의 "결정사항" 칸을 채운 흐름은 `웹지도만들기_AI와_실습절차_수행.md` 2절에서 확인할 수 있다.

민감도 분석(프로젝트1)이나 표본 규모 검토(프로젝트2)와 마찬가지로, 이 프로젝트에서도 필터 기준값(예: 0.5, 0.6, 0.7)을 다르게 설정했을 때 화면에 남는 후보지가 어떻게 달라지는지 비교해 보는 절차가 함께 요구된다.

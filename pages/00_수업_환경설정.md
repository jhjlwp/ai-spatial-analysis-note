# 수업 환경설정 안내

이 문서는 프로젝트1(재난 대피소 입지 적합성 분석), 프로젝트2(뉴스 지명 추출) 등 강좌 전체에서 공통으로 필요한 환경설정을 한곳에 정리한 것이다. 각 프로젝트 학습정리 문서에서는 이 문서를 참고하도록 하고, 프로젝트별로 반복해서 설명하지 않는다.

---

## 1. 이 강좌에서 쓰는 두 가지 파이썬 실행 환경

이 강좌에서는 파이썬을 두 가지 서로 다른 방식으로 사용하므로, 먼저 이 둘을 구분해 둔다.

| 구분 | 실행 위치 | 용도 | 예시 |
|---|---|---|---|
| QGIS 내장 파이썬(PyQGIS) | QGIS 프로그램 안의 Python 콘솔 | QGIS 레이어·지도 자동화 | 인쇄 레이아웃 자동 생성 스크립트 |
| 독립 실행 파이썬(Miniconda) | 터미널/명령 프롬프트 | QGIS와 무관한 데이터 수집·가공 | 뉴스 수집, 지오코딩 스크립트 |

QGIS 내장 파이썬은 QGIS를 설치하면 이미 함께 들어 있어 별도 설치가 필요 없다(QGIS 메뉴의 `플러그인 → Python 콘솔`에서 사용). 반면 웹에서 뉴스를 수집하거나 외부 API를 호출하는 스크립트는 QGIS와 무관하게 동작하므로, 아래에서 설명하는 별도의 파이썬 환경(Miniconda)에서 실행한다. 두 환경을 혼동하지 않도록 주의한다.

---

## 2. QGIS 설치

1. `qgis.org/download`에서 운영체제에 맞는 설치 파일을 내려받는다. 이 강좌는 QGIS 3.44.8 이상을 기준으로 한다.
2. 설치 파일을 실행해 기본 설정으로 설치를 진행한다.
3. 설치 후 QGIS를 실행해 정상적으로 열리는지 확인한다.

## 3. Miniconda로 GIS 실습 환경 만들기

### Anaconda와 Miniconda
Anaconda는 파이썬으로 데이터 분석이나 머신러닝을 하려는 사람을 위해 필요한 프로그램을 한 번에 설치해 주는 묶음이다. 파이썬 본체, 패키지를 설치·관리하는 도구(conda), 자주 쓰는 라이브러리가 함께 들어 있어 개별적으로 설치하지 않아도 된다.

Miniconda는 Anaconda의 가벼운 버전이다. conda와 Python이 돌아가는 데 필요한 최소한의 패키지만 설치하고, 나머지는 필요할 때 직접 설치하는 방식이다.
프로젝트마다 필요한 패키지가 달라질 수 있고, 이후 지오공간 패키지(geopandas 등)까지 다루게 될 가능성을 고려해 Miniconda로 가상환경을 구성한다. 가상환경을 쓰면 패키지 버전 충돌 없이 여러 프로젝트를 독립적으로 관리할 수 있다.

### 전체 단계

| 단계 | 소제목 | 하는 일 |
|---|---|---|
| Step 1 | Miniconda 설치 | 패키지·환경 관리 도구(conda) 설치 |
| Step 2 | 실습 전용 가상환경 만들기 | 수업용 독립 환경 `giscourse` 생성 |
| Step 3 | 핵심 패키지 설치 | 공간 분석·LLM·대시보드·데이터 수집 패키지 설치 |
| Step 4 | 설치 검증 | 설치한 패키지가 정상 동작하는지 확인 |

---

### Step 1. Miniconda 설치

#### 이 단계에서 하는 일
Python 패키지와 가상환경을 관리하는 도구인 conda를 설치합니다.

#### 왜 conda인가?
GeoPandas 공식 문서는 conda를 권장합니다. GDAL·GEOS·PROJ 같은 C 라이브러리를 미리 빌드된 형태로 한 번에 설치해 주기 때문입니다.
참고로 최근에는 shapely, pyproj, pyogrio를 pip wheel로도 설치할 수 있습니다. 그래도 GeoPandas 공식 문서는 여전히 conda를 권장합니다.

#### 사용 방법
1. Anaconda 공식 사이트에서 **Miniconda** 설치 파일을 다운로드합니다. (전체 Anaconda 배포판이 아니라 Miniconda를 받아야 합니다)
2. 운영체제에 맞게 설치합니다.
   - **Windows**
     - 설치 마법사를 진행합니다.
     - **"Add to PATH"는 체크하지 마세요.** Anaconda 공식 문서도 이를 권장합니다. 설치 후에는 시작 메뉴의 **Anaconda Prompt**에서 작업하세요.
     - 설치 경로에는 **영문·숫자만 쓰고 공백을 넣지 마세요.** (예: `C:\miniconda3`) 사용자 이름이 한글이면 기본 경로가 문제를 일으킬 수 있습니다.
   - **Mac**
     - **Apple Silicon(M1~)** 과 **Intel** 설치 파일이 다르므로 본인 칩에 맞게 선택합니다.
     - `.pkg`를 실행하거나 터미널 설치 스크립트를 사용합니다.
     - 설치 후 터미널을 새로 엽니다. (필요 시 `conda init zsh`)

#### 확인 방법
Windows는 Anaconda Prompt, Mac은 Terminal에서 실행합니다.
```bash
conda --version
```
`conda 숫자.숫자.숫자` 형태로 출력되면 정상입니다.

### Step 2. 실습 전용 가상환경 만들기

#### 이 단계에서 하는 일
수업 전용 독립 환경 `giscourse`를 만들어, 다른 프로젝트와 패키지가 섞이지 않게 합니다. 환경의 기본 채널을 conda-forge로 고정하는 설정도 함께 합니다. (GeoPandas 공식 문서 권장 방식)

#### 사용 방법 (최초 1회)
```bash
conda create -n giscourse -c conda-forge python=3.11
conda activate giscourse
conda config --env --add channels conda-forge
conda config --env --set channel_priority strict
```
- GeoPandas 공식 문서는 defaults 채널과 conda-forge를 **섞어 쓰지 말고 한쪽으로 통일**하라고 강조합니다. 위 설정은 이를 위한 것입니다. Python도 처음부터 conda-forge에서 받도록 `create` 명령에 `-c conda-forge`를 넣었습니다.
- **약관 동의 안내**: 최신 Miniconda는 첫 `conda create`/`install` 때 Anaconda 기본 채널(defaults)의 이용약관(ToS) 동의를 요구할 수 있습니다. 화면에 동의 여부를 묻는 메시지가 나오면 안내에 따라 `a`를 입력하고, 오류로 중단되면 `conda tos accept`를 실행한 뒤 명령을 다시 실행하세요.

#### 사용 방법 (매번 작업 시작할 때)
```bash
conda activate giscourse
```
- 프롬프트 앞에 `(giscourse)`가 보이면 활성화된 상태입니다. `(base)`가 보이면 활성화가 안 된 것입니다.
- 터미널을 껐다 켜면 비활성화되므로 매번 다시 실행해야 합니다.

#### 기타 명령
| 명령 | 용도 |
|---|---|
| `conda deactivate` | 현재 환경 나가기 |
| `conda env list` | 만들어진 환경 목록 보기 |

### Step 3. 핵심 패키지 설치

#### 이 단계에서 하는 일
수업에서 사용할 공간 데이터 처리, LLM 에이전트, 대시보드, 데이터 수집 패키지를 설치합니다.

#### 사전 확인
- 프롬프트 앞에 `(giscourse)`가 있는지 확인합니다.
- conda 패키지(3-1)를 **먼저**, pip 패키지(3-2~3-4)를 **나중에** 설치합니다. pip로 설치한 패키지는 conda가 의존성을 관리하지 못합니다. 그래서 나중에 conda로 설치하면 덮어쓰거나 환경이 꼬일 수 있습니다.

#### 3-1. 공간 데이터 패키지 (conda)
```bash
conda install geopandas rasterio shapely pyogrio pyproj
```
- `pyogrio`: GeoPandas 기본 벡터 파일 I/O 엔진 (GDAL 바인딩)
- `fiona`: 선택사항입니다. 구버전 코드/튜토리얼과의 호환이 필요할 때만 `conda install fiona`
- 여러 번 나눠 설치하면 의존성 충돌이 생기기 쉬우니 가능하면 한 명령으로 설치하세요.

#### 3-2. LLM 에이전트 & 대시보드 패키지 (pip)
```bash
pip install anthropic streamlit folium plotly scikit-learn
```
- 위 패키지 대부분은 conda-forge에도 있으므로 pip 설치가 막히면 `conda install`로 대체할 수 있습니다. 다만 `anthropic` SDK는 공식 배포처인 PyPI(pip)에서 설치하는 편이 가장 확실합니다.

#### 3-3. 데이터 수집 패키지 (pip)
```bash
pip install feedparser requests
```
| 패키지 | 역할 |
|---|---|
| `feedparser` | RSS·Atom 피드를 읽어 제목, 링크, 날짜 같은 항목을 Python 객체로 바꿔 줍니다. 뉴스나 공지 피드를 수집할 때 씁니다. |
| `requests` | 웹 페이지나 API에 HTTP 요청을 보내고 응답을 받는 라이브러리입니다. 공공데이터 API 등에서 데이터를 내려받을 때 씁니다. |

- `requests`는 streamlit 같은 다른 패키지의 의존성으로 이미 설치돼 있을 수 있습니다. 이 경우 pip가 `Requirement already satisfied`라고 표시하고 넘어가며, 오류가 아닙니다.
- 3-2와 3-3은 같은 pip 명령이므로 한 줄로 합쳐 설치해도 됩니다.

#### 3-4. 선택 설치: pyshp (pip)
```bash
pip install pyshp
```
- `pyshp`는 ESRI Shapefile(`.shp`)을 읽고 쓰는 가벼운 라이브러리입니다. GDAL 없이 순수 Python으로 동작합니다.
- **3-1에서 GeoPandas를 설치했다면 Shapefile 읽기·쓰기에는 필요하지 않습니다.** `gpd.read_file()`과 `gdf.to_file()`이 pyogrio를 통해 이미 처리합니다.
- 수업 자료나 예제 코드에서 `import shapefile`을 쓰는 경우에만 설치하세요.
- 설치 이름과 import 이름이 다릅니다. 설치는 `pip install pyshp`, 코드에서는 `import shapefile`로 불러옵니다.

#### 패키지 용도
- `geopandas`, `rasterio`, `shapely`: 모듈1(데이터 정제·주제도), 모듈2(입지적합성 분석)
- `anthropic`: Claude API SDK
- `streamlit`, `folium`: 모듈3(웹지도 대시보드)
- `feedparser`, `requests`: 외부 데이터(RSS 피드, 웹 API) 수집
- `pyshp` (선택): Shapefile 읽기·쓰기. GeoPandas로 대체 가능

### Step 4. 설치 검증

#### 이 단계에서 하는 일
설치한 패키지를 import해서 정상 설치 여부를 확인합니다.

#### 사용 방법
1. `conda activate giscourse`로 환경을 활성화합니다.
2. 아래 세 명령을 차례로 실행합니다.
```bash
python -c "import geopandas, rasterio, shapely, pyproj, pyogrio; print('geopandas', geopandas.__version__); print('OK')"
python -c "import anthropic, streamlit, folium, plotly, sklearn; print('OK')"
python -c "import feedparser, requests; print('OK')"
```
- `pyshp`를 설치했다면 `python -c "import shapefile; print('OK')"`로 따로 확인하세요. (`shapefile`은 `pyshp`의 import 이름입니다.)

#### 결과 해석
- 세 명령 모두 `OK`가 출력되면 패키지 설치는 정상입니다. import에 성공했다는 것은 설치됐다는 뜻일 뿐, 실제 동작까지 보장하지는 않습니다. 동작은 아래 선택 확인으로 점검하세요.
- `ModuleNotFoundError: No module named 'xxx'`가 나오면 해당 패키지가 설치되지 않았거나 다른 환경에 설치된 것입니다. `(giscourse)`가 활성화됐는지 확인한 뒤 Step 3의 해당 명령을 다시 실행하세요.

#### 선택: 동작 확인
좌표계 변환(pyproj)과 GeoPandas·shapely 연동까지 확인합니다.
```bash
python -c "import geopandas as gpd; from shapely.geometry import Point; g = gpd.GeoSeries([Point(126.7, 37.4)], crs='EPSG:4326').to_crs('EPSG:5179'); print(g); print('동작 OK')"
```
좌표가 출력되고 `동작 OK`가 나오면 정상입니다.

### 자주 겪는 문제

| 증상 | 해결 |
|---|---|
| `conda` 명령을 찾을 수 없음 (Windows) | Anaconda Prompt에서 실행. PATH를 억지로 추가하지 않기 |
| `command not found: conda` (Mac) | `~/miniconda3/bin/conda init zsh` 실행 후 터미널 재시작 (bash 사용 시 `bash`로 변경) |
| `CondaToSNonInteractiveError` (약관 미동의) | `conda tos accept` 실행 후 명령 재실행 |
| import는 되는데 파일 읽기·좌표 변환에서 에러 | 환경을 지우고 재생성: `conda deactivate` → `conda remove -n giscourse --all` → Step 2부터 다시 진행 |
| `UnsatisfiableError` (의존성 충돌) | 새 환경을 만들어 패키지를 한 번에 설치, 채널 혼용 여부 확인 |
| 한글 사용자명 경로 오류 | Miniconda를 `C:\miniconda3` 같은 영문 경로에 설치 |
| Mac에서 느리거나 이상 동작 | Intel 버전을 설치했는지 확인 (Apple Silicon은 arm64 버전 사용) |

### 삭제 방법

#### 실습 환경(giscourse)만 삭제
```bash
conda deactivate
conda remove -n giscourse --all
```
- 활성화된 환경은 삭제할 수 없으므로 `conda deactivate`를 먼저 실행합니다.
- 삭제 확인 메시지가 나오면 `y`를 입력합니다.
- pip로 설치한 패키지도 환경 폴더 안에 있으므로 함께 삭제됩니다.
- 삭제 후 `conda env list`에 `giscourse`가 보이지 않으면 정상입니다.
- 나중에 같은 패키지 구성으로 다시 만들 계획이면, 삭제 전에 환경을 파일로 내보내 두세요.
```bash
conda env export --name giscourse > giscourse.yaml
```

#### Miniconda 전체 삭제
Miniconda를 지우면 환경도 모두 함께 사라집니다. 필요한 환경은 위 방법으로 먼저 백업하세요.

**Windows**
1. 제어판 → **프로그램 제거**에서 Miniconda(또는 Anaconda) 항목을 선택하고 **제거**를 누릅니다.
2. 화면 안내에 따라 진행합니다.
3. 시작 메뉴에서 "Anaconda Prompt"를 검색했을 때 나오지 않으면 제거된 것입니다.
- 제거 후에도 바탕화면 바로가기나 사용자 폴더의 설정 파일(`.condarc`, `.conda` 등)이 남을 수 있습니다. 필요 없다면 직접 삭제하세요.
- "Just Me" 설치인데도 관리자 권한을 요구하면, 설치 폴더의 `Uninstall-Miniconda3.exe`를 직접 실행해 보세요.

**Mac**
1. 설치 위치를 확인합니다.
```bash
conda info --base
```
2. 결과에 따라 삭제 스크립트를 실행합니다. (Miniconda 24.11.1 이후 버전에 포함)
   - 홈 폴더(`~/miniconda3`)에 설치된 경우
   ```bash
   conda deactivate
   ~/miniconda3/uninstall.sh
   ```
   - `/opt/miniconda3`에 설치된 경우 (macOS `.pkg` 설치 파일 등)
   ```bash
   conda deactivate
   sudo -E /opt/miniconda3/uninstall.sh
   ```
3. 터미널을 닫았다가 다시 열어 프롬프트에 `(base)`가 나타나지 않으면 제거된 것입니다.

**`uninstall.sh`가 없는 경우 (Miniconda 24.11.1 이전 설치)**
```bash
conda activate
conda init --reverse --all
rm -rf ~/miniconda3
rm -rf ~/.condarc ~/.conda ~/.continuum
```
- 설치 위치가 `/opt/miniconda3`이면 `rm -rf` 대신 `sudo rm -rf /opt/miniconda3`를 사용합니다.
- 다시 설치할 계획이면 `~/.condarc`는 남겨 두세요. 사용자 설정이 들어 있습니다.
- ⚠️ `rm -rf`는 확인 없이 삭제하며 되돌릴 수 없습니다. 경로를 한 번 더 확인한 뒤 실행하세요.

**설정 파일과 캐시까지 지우려면 (선택)**
```bash
~/miniconda3/uninstall.sh --remove-caches --remove-config-files user --remove-user-data
```
- 다른 conda를 함께 쓰고 있다면 사용하지 마세요.

# Conda 쉬운 사용 가이드 (Windows)

## 딱 한 번만 설정

1. 시작 메뉴에서 **Anaconda Prompt** 열기
2. 아래 입력 후 Enter
   ```
   conda init cmd.exe
   ```
3. 열려 있는 터미널 **모두 닫기**

## 이후 매번 사용

1. 작업할 폴더를 탐색기로 열기
2. 주소창에 `cmd` 입력 후 Enter
3. 가상환경 목록 확인
   ```
   conda env list
   ```
4. 환경 활성화
   ```
   conda activate 환경이름
   ```

## 자주 쓰는 명령어 모음

| 하고 싶은 일 | 명령어 |
|---|---|
| 가상환경 목록 보기 | `conda env list` |
| 환경 활성화 | `conda activate 환경이름` |
| 환경 비활성화 | `conda deactivate` |
| 설치된 패키지 보기 | `conda list` |

## 참고

- 목록에서 `*` 표시가 있는 환경이 **현재 활성화된 환경**입니다.
- 프롬프트 맨 앞의 `(환경이름)`으로도 현재 환경을 알 수 있습니다.
- PowerShell도 쓸 거라면 설정할 때 `conda init powershell`도 같이 실행하세요.
- cmd를 열 때 `(base)`가 자동으로 뜨는 건 정상입니다.


## 6. GitHub 계정 및 저장소

포트폴리오 정리를 위해 GitHub 계정과 저장소가 필요하다. 아래는 GitHub을 처음 써보는 학습자도 따라할 수 있도록 계정 생성부터 업로드까지 순서대로 정리한 절차이며, 프로젝트 구분 없이 강좌 전체에 동일하게 적용된다. 저장소에 올릴 스크립트 파일명은 차시나 팀마다 다를 수 있으므로, 정해진 이름을 그대로 쓰기보다 실제로 작업한 파일명을 사용한다.

**GitHub이란?**
GitHub은 코드와 문서 파일을 온라인에 저장하고 다른 사람과 공유할 수 있는 서비스다. 이 강좌에서는 지금까지 작성한 스크립트와 결과물을 한곳에 모아, 포트폴리오로 공개하는 용도로 사용한다.

알아두면 도움이 되는 용어는 다음과 같다.

| 용어 | 의미 |
|---|---|
| 저장소 (Repository) | 파일들을 모아두는 프로젝트 단위 폴더. 이 안에 스크립트와 결과물을 담는다 |
| 커밋 (Commit) | 저장소에 파일 추가·수정 등의 변경사항을 확정해서 남기는 것. "저장하기"와 비슷한 개념이다 |
| README | 저장소를 처음 보는 사람에게 "이 프로젝트가 무엇인지" 설명하는 파일. 저장소 메인 화면에 자동으로 표시된다 |
| Public / Private | 저장소를 다른 사람도 볼 수 있게 공개(Public)할지, 본인만 볼 수 있게 비공개(Private)로 둘지 정하는 설정 |

이 강좌에서는 Git 명령어(커맨드라인)를 몰라도, 웹 브라우저 화면만으로 계정 생성부터 파일 업로드까지 모두 진행할 수 있다.

**① GitHub 계정 만들기 (이미 계정이 있다면 건너뛴다)**

1. 웹 브라우저에서 `github.com` 접속
2. 우측 상단 `Sign up` 클릭
3. 이메일 주소, 비밀번호, 사용자명(username)을 순서대로 입력해 계정 생성
4. 가입 시 입력한 이메일로 온 인증 메일을 열어 인증 완료

**② 새 저장소(repository) 만들기**

1. 로그인한 상태에서 우측 상단 `+` 아이콘 클릭 → `New repository` 선택
2. `Repository name`에 저장소 이름 입력 (예: `gis-course-portfolio`처럼 강좌 내용을 알 수 있는 이름 권장)
3. `Public`(공개) / `Private`(비공개) 중 선택 — 포트폴리오로 공개할 목적이면 `Public` 권장
4. `Add a README file` 항목에 체크
5. 하단 `Create repository` 버튼 클릭

**③ 스크립트·결과 파일 업로드 (Git 명령어 없이 웹 화면만으로 가능)**

1. 방금 만든 저장소 페이지에서 `Add file` 버튼 → `Upload files` 클릭
2. 지금까지 각 프로젝트·차시에서 작성한 스크립트 파일(.py)들을 화면으로 끌어다 놓거나, `choose your files`로 직접 선택해 첨부한다. 파일명은 실제로 작업한 이름을 그대로 사용한다.
3. 완성한 결과 파일(PDF 지도, CSV, Shapefile 등)도 같은 방식으로 함께 업로드한다.
4. 화면 하단으로 스크롤 → `Commit changes` 버튼 클릭 → 업로드 완료

**④ README 작성**

1. 저장소 메인 화면에서 `README.md` 파일을 클릭
2. 파일 우측 상단의 연필 모양 아이콘(Edit) 클릭
3. 프로젝트 목적, 사용한 데이터, 주요 결과, 확인된 한계를 3~5줄로 간단히 요약해 작성한다
4. 우측 상단 `Commit changes` 버튼 클릭 → 저장

> 프로젝트별로 저장소를 나눌지, 강좌 전체를 저장소 하나로 관리할지는 자유롭게 정할 수 있다. 여러 프로젝트를 한 저장소에 담을 경우, 4절의 폴더 구조를 그대로 저장소 안의 폴더 구조로 사용하면 된다.

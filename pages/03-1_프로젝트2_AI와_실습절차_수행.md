# 제2부 실습 절차 — AI와 함께 수행하기

이 문서는 이론문서(`03_프로젝트2_뉴스지명추출_.md`) 제2부의 두 실행 절차 표를, 학습자가 AI(Claude 등)에게 질문하며 실제로 채워나가는 과정을 보여준다. 각 단계마다 AI에게 던질 수 있는 질문 예시와, 그 답을 바탕으로 결정에 이르는 흐름을 함께 제시한다. 최종적으로 채워진 결정사항 자체는 `04_프로젝트2_실습절차_예시.md`에서 확인할 수 있다.

---

## 1. 텍스트 기반 위치 정보 추출 실행 절차

### 1) 문제 정의
- **AI에게 물어볼 질문**: "노원구 뉴스 보도의 지역별 편중을 보려면 어떤 텍스트 소스가 적합할까?"
- **흐름**: AI가 뉴스·SNS·민원 게시판 등 채널별 특징(접근 난이도, 지명 언급 비율, 개인정보 이슈)을 비교해 설명하면, 그중 지명이 비교적 명시적으로 등장하는 뉴스를 소스로 선택한다.

### 2) 데이터 수집 경로 확정
- **AI에게 물어볼 질문**: "네이버 뉴스 검색 API를 발급받으려는데 안내대로 진행해도 되는지 확인해줘."
- **흐름**: 실제 신청 화면의 안내 문구를 AI에게 확인받는 과정에서 개인 신규 발급이 정책적으로 막혀 있음을 파악하고, AI의 제안에 따라 뉴스 수집 경로를 구글 뉴스 RSS(가입 불필요)로 전환한다.

### 3) 지명 인식 방법 선택
- **AI에게 물어볼 질문**: "뉴스 제목에서 노원구 동 이름을 추출하려면 정규표현식과 목록 매칭 중 어느 쪽이 나을까?"
- **흐름**: AI가 두 방법의 장단점(오탐지 가능성, 목록 밖 지명 포착 여부)을 비교해주면, 대상이 노원구 동으로 한정되어 있다는 점에서 목록 매칭을 선택한다.

### 4) 수집 표본 규모 사전 설정
- **AI에게 물어볼 질문**: "노원구 관련 뉴스를 검색할 때 한 번에 몇 건 정도 수집하는 게 적당할까?"
- **흐름**: 표본 규모는 코드를 받기 전에도 결정할 수 있는 항목이다. 여기서 정한 값(예: 50건)은 확정값이 아니라 출발점이며, 다음 단계의 코드 요청에 이 값을 함께 포함시킨다.

### 5) 지오코딩 API·방법 선택
- **AI에게 물어볼 질문**: "동 이름을 좌표로 변환하려는데, 카카오·구글·네이버 중 어떤 지오코딩 API를 쓰는 게 좋을까?"
- **흐름**: AI가 각 서비스의 발급 절차, 비용, 요청 제한을 비교해주면(예: 카카오는 REST API 키를 즉시 셀프 발급 가능), 이를 근거로 사용할 API를 코드 요청 전에 미리 정한다.

### 6) 파이프라인 코드 요청
- **AI에게 물어볼 질문**: "지금까지 정한 내용(뉴스 수집 → 동 이름 추출 → 카카오 지오코딩 → 저장)을 구현하는 파이썬 스크립트를 작성해줘. 한 번에 수집할 기사 수는 50건으로 해줘."
- **흐름**: 앞서 정한 표본 규모와 지오코딩 API를 요청 문구에 함께 포함시켜, 두 값이 코드에 반영된 상태로 코드를 받는다.

### 7) 코드 검토 및 필요한 내용 수정
- **AI에게 물어볼 질문**: "받은 코드에서 max_items 값과 지오코딩 API가 내가 요청한 대로 반영되어 있는지 확인해줘.", "표본을 더 늘리려면 코드를 어떻게 바꿔야 해?"
- **흐름**: 코드를 받은 뒤 곧바로 사용하지 않고, 표본 규모와 지오코딩 API 선택을 비롯해 의도한 내용이 코드에 제대로 반영되었는지 점검하는 단계를 거친다. 이 과정에서 `max_items=50`이 서버 제약이 아니라 임의로 정한 값이라는 점을 다시 확인하고, 표본을 늘리는 방법(건수 상향, 동별 분할 검색, `when:` 파라미터로 기간 지정)을 안내받아 필요하면 코드를 수정한다.

### 8) 지오코딩 입력값 검토
- **AI에게 물어볼 질문**: "지오코딩에 동 이름을 그대로 쓰면 어떤 문제가 생길 수 있어?"
- **흐름**: API 선택(5번)과는 별개로, 그 API에 실제로 어떤 값을 입력으로 보낼지도 검토가 필요하다. AI가 같은 동을 언급한 기사는 모두 동일한 좌표로 지오코딩된다는 점, 그리고 캐싱으로 API 호출을 줄일 수 있다는 점을 설명해주면 이를 반영해 진행한다.

### 9) 결과 저장 형식 결정
- **AI에게 물어볼 질문**: "결과를 QGIS에서 바로 불러오려면 어떤 파일 형식으로 저장해야 해?"
- **흐름**: AI로부터 CSV(위도·경도 컬럼 포함)와 Shapefile(좌표계 명시 필요) 각각의 QGIS 로드 방법을 안내받아 두 형식으로 저장하도록 스크립트를 구성한다.

## 2. 공간조인 및 주제도 제작 실행 절차

### 1) 주제도 변수 선택
- **AI에게 물어볼 질문**: "인구밀도를 지도로 표현하려면 어떤 분류기법들을 비교해봐야 해?"
- **흐름**: AI가 등간격·분위수·자연분류의 차이를 설명해주면, 세 기법을 모두 적용해 비교하기로 한다.

### 2) 분류기법 비교
- **AI에게 물어볼 질문**: "세 분류기법으로 만든 지도가 왜 다르게 보이는 거야?"
- **흐름**: AI의 설명(구간을 나누는 기준이 다르다는 점)을 참고해, 실제로 세 지도를 만들어 스크린샷으로 비교한다.

### 3) 조인 방식 선택
- **AI에게 물어볼 질문**: "뉴스 포인트와 행정동을 합치려면 속성조인과 공간조인 중 뭘 써야 해?"
- **흐름**: 두 데이터에 공유하는 코드 컬럼이 없다는 점을 확인받고 공간조인(Intersects)을 선택한다.

### 4) 조인 대상 레이어 확정
- **AI에게 물어볼 질문**: "Join attributes by location에서 Input layer랑 Join layer를 어떻게 지정해야 해?"
- **흐름**: AI의 설명에 따라 Input layer는 뉴스 포인트, Join layer는 행정동 경계로 지정한다.

### 5) 조인 결과 검증
- **AI에게 물어볼 질문**: "이 프로젝트에서 노원구 관련기사를 수집해서 동이름을 사용하여 지오코딩하고 있나?", "그럼 뉴스가 많이 발생한 곳이라는 걸 어떻게 시각화하도록 되어있지?"
- **흐름**: 이 질문들을 통해 현재 설계가 동 단위 대표 좌표만 찍고 있어 빈도가 시각적으로 드러나지 않는다는 한계를 AI와의 대화에서 발견하고, 검증 단계에서 이 점을 함께 확인한다.

### 6) 스토리텔링 구성
- **AI에게 물어볼 질문**: "이 프로젝트의 개요를 정리해줘", "방법론 순서가 논리적으로 맞는지 검토해줘"
- **흐름**: AI에게 프로젝트 개요 초안을 요청하고, 번역체·논리적 일치성(예: 공간조인과 주제도 제작의 의존관계)을 여러 차례 검토받아 다듬은 뒤 스토리텔링 구성에 반영한다.

## 정리

이 과정에서 공통적으로 드러나는 흐름은 다음과 같다.

1. 학습자가 진행 중인 화면·코드·아이디어를 AI에게 그대로 보여주고 질문한다.
2. AI가 여러 선택지의 근거와 장단점을 비교해 설명한다.
3. 학습자는 그 설명을 바탕으로 최종 결정을 내리고, 결정의 이유를 함께 기록한다.

AI가 대신 결정해주는 것이 아니라, 결정에 필요한 근거를 학습자가 판단할 수 있도록 정리해주는 역할을 한다는 점이 이 과정의 핵심이다.

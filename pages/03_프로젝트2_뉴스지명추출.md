# 텍스트 기반 공간정보 추출과 주제도 제작의 개념과 이론

# 제1부. 기본 이론

## 1. 비정형 텍스트 데이터 수집 방법과 제약

### 1.1 정형 데이터와 비정형 데이터

정형 데이터(Structured Data)는 SHP 파일의 속성 테이블이나 위경도 컬럼을 갖춘 표처럼, 사전에 정해진 구조(행·열, 필드 등)에 맞춰 저장된 데이터이다. 반면 비정형 데이터(Unstructured Data)는 뉴스 기사, SNS 게시물, 민원 게시글처럼 정해진 구조 없이 자연어 문장 형태로 존재하는 데이터를 말한다. 비정형 텍스트 데이터는 출처가 조직 밖인지 안인지를 기준으로 외부 데이터와 내부 데이터로 나눌 수 있다. 외부 데이터로는 소셜 미디어, 온라인 커뮤니티, 뉴스 기사, 상품·앱 리뷰, 공공·학술 문서 등이 있다. 내부 데이터로는 고객 상담 기록, 설문의 주관식 응답, 업무 문서, 상담 녹취를 변환한 텍스트 등이 있다. 비정형 텍스트 데이터를 공간분석에 활용하려면, 수집 이후 지오파싱(2절)과 같은 별도의 처리 과정을 거쳐야 한다.

### 1.2 수집 채널의 유형

비정형 텍스트 데이터는 대체로 다음과 같은 채널에서 수집된다.

- **뉴스**: 언론사·포털이 제공하는 API, RSS 피드, 또는 언론사 웹페이지 직접 크롤링
- **소셜미디어(SNS)**: 플랫폼이 제공하는 공식 API, 또는 공개 페이지에 대한 웹 스크레이핑. 다만 위치 태그를 켜둔 게시물의 비율이 낮아, 텍스트에 지명이 명시적으로 언급되지 않으면 지오파싱 자체가 어려운 경우가 많다.
- **행정·공공 텍스트**: 지자체 민원 게시판, 공공기관 보도자료 등(다만 개인정보 문제로 원문이 비공개인 경우가 많음)
- **기타**: 온라인 리뷰, 커뮤니티 게시글, 논문·보고서, 설문 응답 텍스트 등

### 1.3 수집 방식별 특성

데이터를 실제로 모을 때는 여러 수집 기법을 쓴다. 외부 데이터는 주로 웹 크롤링·스크래핑, API, RSS로 수집하고 내부 데이터는 주로 로그 수집, 데이터베이스(DB) 연동 등으로 수집한다.
같은 채널이라도 접근 방식에 따라 특성이 달라진다.

#### (1) 웹 크롤링·스크래핑
**웹 크롤링**은 링크를 따라 여러 웹페이지를 자동으로 돌아다니며 모으는 작업이다. **웹 스크래핑**은 특정 페이지에서 필요한 정보만 골라 뽑아내는 작업이다. 일반적으로 ① HTTP 요청 → ② HTML 파싱(구조 분석) → ③ 데이터 추출 → ④ 저장의 순서로 진행한다.

서버가 완성된 HTML을 보내 주는 **정적 페이지**는 requests와 BeautifulSoup으로 수집할 수 있지만, 자바스크립트가 실행된 뒤에 내용이 채워지는 **동적 페이지**는 Selenium이나 Playwright 같은 브라우저 자동화 도구가 필요하다. 수집할 때는 robots.txt와 이용약관, 저작권, 개인정보보호법을 지켜야 한다. 또한 요청 간격을 두어 상대 서버의 부담을 줄여야 한다.

#### (2) API

**API(Application Programming Interface)**는 서비스 제공자가 데이터를 내보내기 위해 공식적으로 마련한 창구이다. 검색어·기간·정렬 등의 조건을 지정해 요청하면 JSON이나 XML 형식으로 결과를 받는다. 뉴스 수집에 쓰는 대표적인 API로는 네이버 검색 API, 빅카인즈, 가디언 Open Platform, 뉴욕타임스 API, NewsAPI 등이 있다.

#### (3) RSS

**RSS(Really Simple Syndication)**는 웹사이트가 새 글 목록을 XML 형식으로 공개해 두는 구독용 피드이다. 인증 없이 주소만으로 최신 기사를 받을 수 있지만, 과거 기사를 검색하거나 조건을 지정할 수는 없다.

#### (4) 수집 기법의 비교

| 구분 | 웹 크롤링·스크래핑 | API | RSS |
|---|---|---|---|
| 데이터를 얻는 방식 | 웹페이지에서 직접 추출 | 조건을 지정해 요청 | 공개된 최신 목록 구독 |
| 제공자의 공식 지원 | 없음 | 있음 | 있음 |
| 데이터 형태 | HTML 정제 필요 | 정리된 형태로 제공 | 정리된 형태로 제공 |
| 과거 데이터 | 웹페이지가 남아 있으면 가능 | 조회 가능 | 최신 글만 제공 |
| 제약과 위험 | 사이트 개편 시 코드 수정 필요, 차단·약관 위반 소지 | 키 발급 필요, 호출 한도·비용 | 조건 검색 불가 |

여러 출처의 텍스트를 동시에 수집해야 하는 경우 각 출처마다 페이지 구조가 달라 개별 파서를 모두 작성해야 하는 부담이 있다. 이 때문에 실무에서는 다수의 출처를 이미 통합해 제공하는 집계 서비스(예: 뉴스 통합 검색 RSS, 뉴스 API 서비스)를 활용하는 경우가 많다. API와 RSS는 기사 본문 대신 제목과 요약만 주는 경우가 많다. 본문이 필요하면 기사 링크에 접속해 본문을 따로 스크래핑한다. 따라서 실무에서는 공식 창구인 API를 먼저 쓰고 부족한 부분을 크롤링으로 보완하는 방식이 일반적이다.
조건 검색이나 과거 데이터가 필요하면 API를 사용하고, 최신 데이터를 꾸준히 쌓으려면 RSS를 활용한다. 어떤 기법을 쓰든 법적·윤리적 기준을 지켜야 한다.

### 1.4 수집 시 고려해야 할 제약

- **접근 정책 변경**: 데이터 제공처(포털, API 서비스 등)의 정책은 사전 고지 없이 변경될 수 있으며, 이에 따라 이전에 가능했던 접근 방식이 더 이상 동작하지 않을 수 있다.
- **대안 경로 확보**: 하나의 데이터 소스에 의존하기보다, 접근이 막혔을 때 전환할 수 있는 대안 경로(다른 API, RSS 피드 등)를 미리 파악해 두는 것이 실무적으로 유용하다.
- **저작권**: 텍스트 원문(특히 기사 본문)을 대량으로 수집·저장·재배포하면 저작권 문제가 발생할 수 있다.
- **이용약관 및 접근 제한 규칙**: 각 서비스의 이용약관과 `robots.txt`에 명시된 크롤링 허용 범위를 확인해야 하며, 이를 벗어난 수집은 제약 위반에 해당할 수 있다.
- **개인정보 보호**: SNS나 민원 게시글에는 개인을 식별할 수 있는 정보가 포함될 수 있어, 수집·저장 단계에서 개인정보 보호에 유의해야 한다.
- **접속 차단**: 짧은 시간에 다수의 요청을 보내면 접근이 일시적으로 차단될 수 있어, 요청 간격 조절 등의 장치가 필요하다.

이러한 제약은 방법론 자체의 결함이 아니라, 통제되지 않은 외부 서비스를 데이터 소스로 활용하는 데 따르는 일반적인 특성으로 이해된다. 따라서 결과를 제시할 때는 산출값과 함께 데이터 수집 과정에서의 제약과 그로 인한 한계도 명시해야 한다.

## 2. 지오파싱과 지명 인식

### 2.1 정의

지오파싱(Geoparsing)은 비정형 텍스트(뉴스 기사, SNS 게시물, 민원 게시글 등) 속에서 지명이나 주소와 같은 위치 표현을 식별하고, 이를 지리적 실체와 연결하는 과정이다. 지오파싱은 일반적으로 두 단계로 구성된다.

- **지명 인식(Toponym Recognition)**: 텍스트에서 지명에 해당하는 문자열을 찾아내는 단계
- **지명 해석(Toponym Resolution)**: 인식된 지명이 실제로 어느 위치를 가리키는지 특정하는 단계(동명이지 문제, 즉 Toponym Ambiguity의 해결 포함)

### 2.2 지명 인식 방법

- **목록 매칭(Gazetteer/List Matching)**: 미리 구축한 지명 목록과 텍스트를 대조하여 일치하는 문자열을 찾는 방법이다. 목록에 없는 지명은 인식하지 못하지만, 대상 범위가 한정된 경우(예: 특정 시·군·구에 속한 행정동)에는 오탐지가 적어 정확도가 높다.
- **규칙 기반(정규표현식)**: "~시", "~구", "~동"과 같은 접미사 패턴을 이용해 지명을 추출하는 방법이다. 목록에 없는 지명도 포착할 수 있으나, 지명이 아닌 문자열을 지명으로 오인할 가능성이 있다.
- **개체명 인식(Named Entity Recognition, NER)**: 자연어처리 모델을 이용해 문맥으로부터 지명을 포함한 개체명을 인식하는 방법이다. 목록 매칭이나 규칙 기반보다 일반화된 인식이 가능하나, 모델의 학습 및 적용에 추가적인 자원이 필요하다.

### 2.3 지명 해석 방법

인식된 지명이 여러 후보 위치와 대응될 수 있는 경우(동명이지 문제), 실제로 어느 위치를 가리키는지 판별하기 위해 다음과 같은 방법이 사용된다.

- **최다 인구 원칙(Population Heuristic)**: 동명의 후보 지역 중 인구가 가장 많거나 가장 널리 알려진 곳을 기본값으로 선택하는 방법이다. 구현이 간단하지만, 실제로는 덜 알려진 지역을 가리키는 경우 오판별이 발생한다.
- **문맥 기반 판별**: 텍스트 내에서 함께 언급된 다른 지명·기관명·지역번호 등 주변 문맥 정보를 활용해 후보를 좁히는 방법이다.
- **공간적 근접성(Spatial Clustering) 기반 판별**: 하나의 텍스트에 여러 지명이 함께 등장하는 경우, 서로 지리적으로 가까운 후보들을 하나의 지역으로 묶어 판별하는 방법이다. 하나의 담화에는 하나의 지리적 범위가 우세하게 나타난다는 가정을 전제로 한다.
- **학습 기반 판별**: 인식된 지명 주변의 언어적 특징을 학습한 모델을 이용해 후보를 확률적으로 판별하는 방법이다.

검색 대상을 처음부터 하나의 행정구역 내 지명 목록으로 한정하는 것도, 동명이지 문제 자체를 사전에 차단하는 실무적인 방법으로 활용될 수 있다.

## 3. 지오코딩(Geocoding)

### 3.1 정의

지오코딩은 주소나 지명과 같은 텍스트 형태의 위치 표현을 위도·경도 좌표로 변환하는 과정이다. 반대로 좌표를 주소로 변환하는 과정은 역지오코딩(Reverse Geocoding)이라 한다.

### 3.2 지오코딩 방법과 특성

- 대부분의 지오코딩 서비스는 사전에 구축된 주소 데이터베이스와 입력 텍스트를 매칭하는 방식으로 동작하며, 지도 서비스 제공업체(예: 카카오, 구글, 네이버 등)가 API 형태로 이를 제공한다.
- 지오코딩 결과의 정확도는 입력 텍스트의 구체성에 따라 달라진다. 상세 주소가 아닌 행정동 이름과 같이 넓은 범위의 지명을 지오코딩하면, 결과 좌표는 해당 행정동의 대표점(예: 중심점 또는 행정복지센터 위치)으로 근사되는 경우가 많다는 점에 유의해야 한다.
- 동일한 위치를 반복적으로 조회하는 경우, 캐싱(caching)을 통해 API 호출 횟수를 줄이는 것이 일반적인 최적화 방법이다.

## 4. 공간조인(Spatial Join)

### 4.1 속성조인과의 차이

- **속성조인(Attribute Join)**: 두 테이블이 공유하는 공통 컬럼(예: 행정동 코드)의 값이 일치하는 행을 결합하는 방법이다.
- **공간조인(Spatial Join)**: 공통 컬럼 없이, 두 공간 데이터 간의 위치 관계(포함·교차·인접 등)를 기준으로 속성을 결합하는 방법이다.

### 4.2 공간 조건자(Spatial Predicate)

공간조인을 수행할 때는 두 레이어 간의 위치 관계를 판정하는 기준(조건자)을 지정해야 한다. 대표적인 조건자는 다음과 같다.

| 조건자 | 의미 |
|---|---|
| Intersects | 두 도형이 한 점이라도 겹치는가 |
| Contains / Within | 한 도형이 다른 도형을 완전히 포함하는가 |
| Touches | 두 도형의 경계가 맞닿아 있는가(내부는 겹치지 않음) |

포인트 레이어를 폴리곤 레이어에 결합할 때는 일반적으로 Intersects 또는 Within 조건자가 사용된다.

## 5. 주제도(Thematic Map)와 분류기법

### 5.1 정의

주제도는 특정 주제(인구, 소득, 질병 발생률 등)의 공간적 분포를 표현하기 위해 제작하는 지도이다. 코로플레스맵(Choropleth Map)은 행정구역과 같이 미리 정의된 경계 단위별로 값을 색상 단계로 표현하는 대표적인 주제도 유형이다.

### 5.2 분류기법(Classification Methods)

연속적인 수치 데이터를 몇 개의 단계(class)로 나누어 색상에 대응시키는 절차를 분류(classification)라 하며, 분류기법에 따라 지도의 시각적 인상이 달라질 수 있다.

- **등간격(Equal Interval)**: 값의 전체 범위를 동일한 크기의 구간으로 나누는 방법이다. 계산이 단순하나, 데이터가 한쪽으로 치우쳐 분포하는 경우 특정 구간에 대다수의 대상이 몰릴 수 있다.
- **분위수(Quantile)**: 각 구간에 동일한 개수의 대상이 포함되도록 나누는 방법이다. 구간별 대상 수는 균등하지만, 구간의 값 범위는 균등하지 않을 수 있다.
- **자연분류(Natural Breaks, Jenks)**: 값이 유사한 대상끼리는 같은 구간으로, 값의 차이가 큰 지점은 구간의 경계로 삼도록 통계적으로 최적화하는 방법이다. Jenks(1967)가 제안하였다.

동일한 데이터라도 어떤 분류기법을 적용하는지에 따라 지도에서 강조되는 지역이 달라질 수 있으므로, 여러 분류기법을 비교한 뒤 목적에 맞는 방법을 선택하는 것이 권장된다.

---

## 6. 데이터 시각화와 스토리텔링

### 6.1 One Map One Message 원칙

지도 한 장에는 하나의 핵심 메시지만 담는 것이 정보 전달에 효과적이라는 원칙이다. 여러 주제를 하나의 지도에 동시에 표현하면 정보가 과다해져 해석이 어려워질 수 있다.

### 6.2 데이터 스토리텔링의 구조

데이터를 활용한 시각적 설명은 일반적으로 다음 3단 구조를 따른다.

1. **문제제기**: 어떤 질문에 답하고자 하는지 제시한다.
2. **분석과정**: 문제에 답하기 위해 수행한 데이터 수집·처리·분석 과정을 설명한다.
3. **시사점**: 분석 결과가 의미하는 바와 한계를 제시한다.

---

## 7. 표본 크기와 결과의 대표성

수집된 표본의 수가 적을 경우, 산출된 결과가 전체 모집단(예: 특정 지역의 전체 뉴스 보도)의 특성을 대표한다고 보기 어렵다. 표본이 제한적인 상황에서는 다음과 같은 태도가 권장된다.

- 정량적 결론을 단정적으로 제시하지 않는다.
- 표본의 한계를 명시하고, 결과를 경향성의 시사 또는 향후 확장이 필요한 예비 분석으로 제시한다.
- 가능하다면 검색 범위 확장(예: 하위 지역별 개별 검색), 수집 기간 확대 등을 통해 표본을 늘리는 방법을 함께 제시한다.

# 제2부. 실습 절차

제1부에서는 텍스트 기반 위치 정보 추출과 주제도 제작에 필요한 개념을 살펴보았다. 이제부터는 이 개념들을 실제 프로젝트에 적용한다.

## 프로젝트 개요

**목적**
서울 노원구를 대상으로 뉴스 보도가 구 내 특정 지역에 편중되어 나타나는지 확인한다. 그 편중이 인구 분포와 관련이 있는지도 함께 살펴본다. 이는 "노원구 뉴스는 어디를 얼마나 다루고 있는가" 그리고 "인구가 많은 동일수록 뉴스에도 더 많이 언급되는가"라는 질문에서 출발한다. 노원구를 다른 지역과 비교하는 것이 아니라 **노원구 내 동 단위**로 뉴스 언급 빈도와 인구밀도의 공간적 분포를 함께 살펴본다.

**사용 데이터**
- **뉴스 데이터**: 구글 뉴스 RSS로 수집한 "노원구" 관련 기사. 제목에서 동 이름을 추출한 뒤 좌표로 변환(지오코딩)하여 지도에 점으로 표시한다.
- **인구 데이터**: 프로젝트1에서 구축한 노원구 행정동 경계 및 인구 데이터. 등간격·분위수·자연분류 세 가지 분류기법으로 인구밀도를 지도화한다.

**분석 구성**
뉴스 포인트에 공간조인으로 소속 동 정보를 결합하여, 인구밀도 지도와 같은 공간 단위(동)에서 비교할 수 있게 한다. 두 지도를 비교하여 인구가 많은 동일수록 뉴스에도 더 많이 언급되는지를 시사한다.

**적용 방법론**
1. 지오파싱 — 뉴스 텍스트에서 지명 추출
2. 지오코딩 — 지명을 좌표로 변환
3. 주제도 제작 — 분류기법별 인구밀도 시각화 (인구 데이터, 1·2와 독립적으로 진행)
4. 공간조인 — 뉴스 포인트에 소속 동 정보 결합, 인구밀도와 비교 가능하게 함

**한계**
뉴스 제목에 지명이 명시적으로 언급되는 비율이 낮아 표본 수가 제한적일 수 있다. 이 프로젝트는 확정적인 통계적 결론이 아니라 경향성을 시사하는 예비 분석의 성격을 가진다. 표본의 한계는 결과와 함께 명시하는 것을 원칙으로 한다.

---

앞서 배운 텍스트 수집·지오파싱·지오코딩·공간조인·주제도 제작 절차를 실행 순서로 재구성한 표를 아래에 제시하며, 각 단계에서 어떤 근거로 어떤 값을 결정했는지 "결정사항" 칸에 직접 기록해 나간다.

## 1. 텍스트 기반 위치 정보 추출 실행 절차 (제1부 1~3, 7절 관련)

| 순서 | 실행 내용 | 확인·결정할 사항 | 결정사항 (기입) |
|---|---|---|---|
| 1 | 문제 정의 | 분석 목적, 대상 텍스트 출처(뉴스·SNS·민원 등), 검색 키워드 |  |
| 2 | 데이터 수집 경로 확정 | 사용 가능한 API/RSS 여부, 접근 제약(가입·승인 절차, 정책 변경 등) |  |
| 3 | 지명 인식 방법 선택 | 목록 매칭/정규표현식/개체명 인식 중 선택, 대상 지명 목록의 범위 |  |
| 4 | 수집 표본 규모 결정 | 검색 결과 최대 건수, 검색 단위(전체 지역명 검색 vs 행정동별 분할 검색) |  |
| 5 | 지오코딩 수행 | 사용할 지오코딩 서비스, 캐싱 등 API 호출 최적화 방법 |  |
| 6 | 결과 저장 형식 결정 | GIS 소프트웨어에서 바로 불러올 수 있는 저장 형식, 좌표계 명시 여부 |  |

> 노원구 뉴스를 대상으로 위 표의 "결정사항" 칸을 채운 예시는 프로젝트2 학습정리(1장)에서 확인할 수 있다.

## 2. 공간조인 및 주제도 제작 실행 절차 (제1부 4~6절 관련)

주제도 제작(인구 데이터)과 공간조인(뉴스 데이터)은 서로 독립적으로 진행할 수 있는 작업이다. 아래 표는 개요의 방법론 순서에 맞춰 주제도 제작을 먼저 배치했으나, 실제로는 두 트랙을 병행해도 무방하다.

| 순서 | 실행 내용 | 확인·결정할 사항 | 결정사항 (기입) |
|---|---|---|---|
| 1 | 주제도 변수 선택 | 시각화할 값(인구밀도 등), 분류기법 후보(등간격/분위수/자연분류) |  |
| 2 | 분류기법 비교 | 동일 변수에 여러 분류기법을 적용했을 때 지도 해석이 어떻게 달라지는지 확인 |  |
| 3 | 조인 방식 선택 | 속성조인 vs 공간조인, 사용할 공간 조건자 |  |
| 4 | 조인 대상 레이어 확정 | 포인트 레이어(추출된 위치)와 결합할 폴리곤 레이어(행정경계 등) |  |
| 5 | 조인 결과 검증 | 각 포인트에 올바른 속성(행정동 이름 등)이 결합되었는지 확인 |  |
| 6 | 스토리텔링 구성 | 문제제기-분석-시사점 구조에 따른 지도 배치, 표본 대표성의 한계 명시 여부 |  |

> 노원구 뉴스·인구밀도 사례로 위 표의 "결정사항" 칸을 채운 예시는 프로젝트2 학습정리(2~3장)에서 확인할 수 있다.

민감도 분석(프로젝트1 문서 제1부 7절 참고)과 마찬가지로, 이 프로젝트에서도 수집 표본 규모(1절의 4번 항목)를 다르게 설정했을 때 결과가 어떻게 달라지는지 비교하는 절차가 함께 요구된다.

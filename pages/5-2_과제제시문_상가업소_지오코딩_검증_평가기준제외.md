# 과제 제시문: 상가업소 주소 지오코딩 및 결과 검증 프로그램 개발

## 배경

공공데이터 중에는 도로명주소만 있고 좌표가 없는 자료가 많다. 이러한 자료를 지도 위에 나타내려면 주소를 좌표로 변환하는 **지오코딩(Geocoding)** 과정이 필요하다. 지오코딩은 카카오, 브이월드, 구글 등 여러 서비스가 제공하는데, 서비스마다 주소 데이터와 좌표를 산정하는 기준점이 달라 같은 주소라도 결과가 조금씩 다르다. 따라서 지오코딩 결과는 얻는 것에서 그치지 않고 반드시 검증해야 한다.

소상공인시장진흥공단은 전국 상가업소의 정보를 정리한 **`소상공인시장진흥공단_상가(상권)정보`** 데이터셋을 공공데이터포털(data.go.kr)을 통해 무료로 제공한다. 이 데이터에는 상호명, 업종코드, 업종명, 지번주소, 도로명주소, 경도·위도 등이 들어 있으며 분기 단위로 갱신된다.

본 과제에서는 이 데이터의 도로명주소를 카카오 로컬 API로 다시 지오코딩하고, 그 결과를 데이터에 이미 들어 있는 원본 좌표와 비교하여 지오코딩이 얼마나 정확한지 직접 검증한다. 이를 위해 **파이썬 프로그램**을 설계하고 구현한다.

또한 같은 주소를 구글 시트(Apps Script)로도 지오코딩하여, 서로 다른 두 서비스의 결과가 얼마나 일치하는지 비교한다. 구글 시트에는 지오코딩 전용 내장 함수가 없으므로, 구글이 제공하는 Apps Script의 지도(Maps) 서비스를 이용한다.

## 과제 목표

상가업소 CSV 파일을 대상으로 다음 다섯 가지를 수행하는 것이 과제의 목표이다. 1~3은 파이썬 프로그램으로 구현하고, 4~5는 구글 시트와 검증 보고서로 수행한다.

1. 도로명주소를 카카오 로컬 API(주소 검색)를 이용해 좌표(위도·경도)로 변환(지오코딩)한다.
2. 결과를 CSV와 GeoPackage(`.gpkg`) 두 형식으로 저장한다.
3. 데이터에 포함된 원본 좌표와의 차이(m)를 계산하여 통계로 정확도를 검증한다.
4. 같은 주소를 구글 시트(Apps Script)로도 지오코딩하여 카카오 로컬 API의 결과와 비교한다.
5. 차이가 큰 사례의 원인을 분석하여 검증 보고서에 설명한다.

## 데이터

- 공공데이터포털에서 **`소상공인시장진흥공단_상가(상권)정보`** 데이터셋을 내려받아 사용한다. 전국 단위 또는 특정 시도 단위로 파일이 나뉘어 제공되며, 호출 시간과 한도를 고려하여 특정 시도 단위 파일(예: 세종)을 사용하는 것을 권장한다.
- 주요 컬럼은 `상호명`, `지점명`, `상권업종대분류명`, `지번주소`, `도로명`, `도로명주소`, `경도`, `위도` 등이다.
- 이 데이터에는 각 상가업소의 좌표(경도·위도)가 **이미 포함**되어 있다. 원래는 지오코딩이 필요하지 않으나, 본 과제에서는 일부러 지오코딩을 수행하고 제공된 좌표를 비교 기준(검증 기준)으로 사용한다.
- 파일의 문자 인코딩은 UTF-8이 아닌 CP949(EUC-KR)일 수 있다.
- 구글 시트의 지오코딩에는 일일 호출 한도가 있다. Apps Script의 지도 지오코딩은 개인 계정(gmail.com)에서 하루 1,000회, Google Workspace 계정에서 하루 10,000회로 제한된다. 따라서 구글 시트 비교는 전체 데이터가 아니라 **무작위로 추출한 표본**(예: 300행 내외)으로 수행한다.

## 기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 데이터 입력 | 실행 시 CSV 파일 경로를 입력받아 읽어 들일 수 있어야 한다. UTF-8과 CP949 인코딩을 모두 처리해야 한다 |
| 컬럼 검증 | 주소 컬럼(`도로명주소`)을 찾지 못하면 사용자에게 알리고 종료해야 한다. 주소 컬럼은 자동으로 찾되, 직접 지정할 수 있는 방법도 제공한다 |
| 주소 전처리 | 주소에서 괄호 `( )`와 쉼표 뒤의 상세주소(층, 호수 등)를 제거한 뒤 검색한다. 카카오 문서도 건물명 등 상세주소는 빼고 질의하기를 권장한다 |
| 지오코딩 | 카카오 로컬 API(주소 검색)로 도로명주소를 좌표로 변환한다. 도로명주소 검색이 실패하면 `지번주소`로 다시 시도한다 |
| 안정성 | 동일한 주소는 한 번만 조회한다. 일시적 오류(통신 오류, 서버 오류 등)는 재시도하고, 인증 오류가 나면 즉시 중단하고 원인을 안내한다 |
| 이어하기 | 조회 결과를 파일로 저장해 두어, 중단 후 다시 실행하면 이미 처리한 주소는 건너뛴다. 실행을 중간에 멈추더라도 그때까지의 결과는 저장되어야 한다 |
| 결과 저장 (CSV) | 원본의 전체 행에 카카오 좌표, 지오코딩 상태(성공/실패/오류), 매칭된 주소, 원본 좌표와의 차이(m)를 추가하여 저장한다. 엑셀에서 한글이 깨지지 않아야 한다 |
| 결과 저장 (GeoPackage) | 지오코딩에 성공한 행만 점(Point) 레이어로 저장한다. 좌표계는 EPSG:4326이며, 원본 속성과 차이(m) 값을 포함한다 |
| 출력 형식 | 채점의 일관성을 위해 결과 CSV에는 다음 컬럼 이름을 사용한다: `위도_kakao`, `경도_kakao`, `지오코딩상태`(값은 성공/실패/오류), `매칭주소`, `원본좌표차이_m`. GeoPackage에는 차이 값을 `diff_m` 속성으로 저장한다. 구글 시트 표본 결과 파일에는 `위도_google`, `경도_google` 컬럼을 사용한다 |
| 정확도 검증 | 원본 좌표 컬럼(`경도`, `위도`)을 이용해 행마다 두 좌표 사이의 거리(m)를 계산하고, 중앙값·평균·90% 값·최대값과 거리 구간별 분포를 출력한다 |
| 사례 확인 | 차이가 큰 상위 사례를 원본 주소, 매칭된 주소와 함께 출력한다 |
| 표본 추출 | 전체 데이터에서 비교용 표본을 무작위로 추출한다. 결과를 재현할 수 있도록 난수 시드를 고정하고, 추출한 표본을 파일로 저장한다 |
| 구글 시트 변환 | 표본의 주소를 구글 시트에 올리고, Apps Script의 `Maps.newGeocoder()`를 이용해 좌표로 변환한다. 카카오 변환에 사용한 것과 동일한 전처리 주소를 입력한다 |
| 서비스 간 비교 | 표본에 대해 원본–카카오, 원본–구글, 카카오–구글 사이의 거리(m)를 계산하고, 서비스별 성공률과 거리 통계(중앙값, 평균, 90% 값, 최대값)를 비교한다 |
| 실패 처리 | 주소가 비어 있거나, 검색 결과가 없거나, 통신 오류가 난 행을 구분하여 상태로 기록한다 |

## 구현 조건

- **파이썬 3.9 이상**으로 구현한다. 외부 패키지(`requests`, `pandas`, `geopandas` 등)를 사용할 수 있으나, 필요한 패키지와 설치 방법을 README에 적는다.
- 지오코딩은 **카카오 로컬 API의 주소 검색**을 사용한다. Kakao Developers에서 애플리케이션을 만들어 **REST API 키**를 발급받고, 앱 설정에서 **카카오맵 사용 설정을 켜야** 호출할 수 있다.
- 카카오 지도·로컬 API의 **무료 쿼터는 개발자 계정에서 처음으로 카카오맵을 활성화한 앱에만** 제공된다(2026년 7월 21일 변경). 같은 계정의 두 번째 앱부터는 비즈월렛 연결과 유료 설정이 필요하며 사용량에 따라 요금이 부과될 수 있다. 따라서 이미 카카오맵을 활성화한 앱이 있다면 그 앱을 사용한다. 호출량은 일간·월간 쿼터로 제한되며, 쿼터가 소진되면 429 오류가 발생한다.
- **API 키는 소스 코드에 직접 적지 않는다.** 환경변수 또는 `.env` 파일에서 읽도록 구현하고, 키가 들어 있는 파일은 제출물과 저장소에 포함하지 않는다.
- 결과 좌표계는 EPSG:4326(WGS84 경위도)으로 저장한다.
- 두 좌표 사이의 거리는 위도·경도 숫자의 차이를 임의로 환산하지 않고, **구면 거리 공식(Haversine 등)** 또는 **투영좌표계(예: EPSG:5179)로 변환한 뒤** 계산한다.
- 전체 파일을 실행하기 전에 **소량(약 100행)으로 먼저 시험 실행**하여 키 설정, 성공률, 예상 소요 시간을 확인한다.
- 구글 시트에는 지오코딩 전용 내장 함수가 없다. 구글이 제공하는 **Apps Script의 지도 서비스**(`Maps.newGeocoder().geocode(주소)`)를 사용하여 구현한다. 지오코딩 부가기능(예: Geocode by Awesome Table)을 사용할 수도 있으나, 부가기능은 제3자가 제공하는 것이므로 사용한 부가기능의 이름과 한계를 보고서에 밝힌다.
- 필요하면 `setRegion('kr')`, `setLanguage('ko')`로 검색 지역과 언어를 지정한다. 호출 한도와 단시간 과다 호출을 피하기 위해 호출 사이에 `Utilities.sleep()`으로 간격을 둔다.
- 각 서비스(카카오, 구글)의 이용약관과 쿼터를 확인하고 준수한다.
- 결과 GeoPackage는 **QGIS에서 열어 확인**한다.

## 제출물

- 완성된 파이썬 소스 코드(`.py` 파일)
- 실행 결과 파일: 결과 **CSV**와 **GeoPackage(`.gpkg`)**. 캐시 파일과 API 키는 제출하지 않는다.
- 구글 시트 변환에 사용한 Apps Script 코드(또는 부가기능의 이름)와 표본의 변환 결과 파일
- **검증 보고서**: 다음 내용을 포함한다.
  - 사용한 데이터(파일명, 행 수, 인코딩)와 실행 조건(옵션, 실행 환경)
  - 지오코딩 결과 건수(성공·실패·오류)와 실패 원인
  - 원본 좌표와의 차이 통계(중앙값, 평균, 90% 값, 최대값)와 구간별 분포
  - 구글 시트 변환 방법(사용한 스크립트 또는 부가기능, 표본 크기와 추출 방법)과 서비스별 성공률
  - 원본–카카오, 원본–구글, 카카오–구글 거리 통계를 비교한 표, 두 서비스의 결과가 크게 다른 사례의 분석
  - 차이가 큰 상위 5~10건의 사례 분석표(행 번호, 원본 주소, 매칭된 주소, 차이, 원인 분류, 근거)
  - QGIS에서 차이 값에 따라 색을 달리해 표시한 지도 캡처
  - 결론: 이 데이터에서 카카오 로컬 API의 지오코딩 결과를 얼마나 신뢰할 수 있는지, 구글 시트 변환 결과와 비교했을 때의 특징, 한계와 개선 방안
- 간단한 사용 설명서(README): 사용한 데이터, 설치·실행 방법, API 키 설정 방법을 포함한다.

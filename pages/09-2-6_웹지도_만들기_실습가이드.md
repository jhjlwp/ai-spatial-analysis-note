# 웹지도 만들기 — 실습 가이드

본 가이드는 "프로젝트3: 웹지도 만들기" 학습 자료의 실습 절차만 추려 정리한 요약본이다. 개념 설명과 미션·힌트는 생략하고, 실제 진행에 필요한 절차·프롬프트 템플릿·확인 체크리스트만 담는다. 배경 개념이 필요한 경우 원본 학습 자료(따라하기 문서)를 참고한다.

## 사전 준비물

- [ ] QGIS로 완료한 적합도 분석 결과 레이어 (예: 격자 또는 포인트, 대피소, 행정경계)
- [ ] QGIS2Web 플러그인 (미설치 시 `Plugins → Manage and Install Plugins`에서 "qgis2web" 검색·설치)
- [ ] GitHub 계정
- [ ] AI 채팅(Claude 등) 사용 환경

---

## 1단계 — QGIS2Web으로 1차 웹지도 만들기

1. 왼쪽 레이어 패널에서 웹지도에 넣을 레이어만 체크(표시)하고 나머지는 체크 해제한다.
   - 적합도 색상 지도 레이어
   - 기존 대피소 마커 레이어
   - 행정경계 레이어
2. 상단 메뉴에서 `Web → QGIS2Web → Create web map` 실행
3. 옵션 창(여러 탭)에서 설정
   - **Layers and Groups**: 각 레이어 옆 Popup 드롭다운에서 표시할 필드 선택 (예: `suitability`), 불필요한 레이어는 "No popup"
   - **Appearance**: Basemap은 OpenStreetMap 등 기본값
   - **Export**: Exporter는 Leaflet, 저장 폴더 지정 후 Export 클릭
4. 저장 폴더 안의 `index.html`을 더블클릭하여 브라우저로 확인

**확인 체크리스트**
- [ ] 지도가 뜨는가
- [ ] 적합도 색상이 QGIS에서 본 것과 비슷한가
- [ ] 색칠된 점(또는 격자)을 클릭했을 때 값이 팝업으로 뜨는가
- [ ] 기존 대피소 마커도 함께 보이는가

## 2단계 — AI로 직접 Leaflet 코드 만들기

### GeoJSON 내보내기
1. 웹지도에 쓸 레이어 우클릭 → `Export → Save Features As`
2. Format: GeoJSON
3. CRS: **EPSG:4326**으로 변경 (웹지도는 반드시 4326)
4. 저장

### AI에게 요청하기 (프롬프트 템플릿)

GeoJSON 파일 내용을 통째로 붙여넣거나 첨부하면서 아래 형식으로 요청한다.

```
역할: 너는 Leaflet 전문 프론트엔드 개발자야.
맥락: 첨부한 GeoJSON은 [지역/주제] 분석 결과야.
    각 포인트는 [필드명](0~1, 적합도 점수) 필드를 가지고 있어.
요청: Leaflet을 사용해서 이 GeoJSON을 지도에 표시하는 HTML 코드를 작성해줘.
    - [필드명] 값에 따라 마커 색상이 노랑(낮음)→빨강(높음)으로 변하게 해줘
    - 마커 클릭 시 [필드명] 값을 팝업으로 보여줘
    - 배경지도는 OpenStreetMap 사용
제약: CDN 방식으로 Leaflet을 불러오고, 단일 HTML 파일로 완성해줘.
검증: 완성 후 위 요청 사항(색상 그라데이션, 팝업, 배경지도, 단일 파일 여부) 각각이
     코드 어느 부분에 반영됐는지 하나씩 대조해서 확인해줘.
     실제 데이터가 아닌 예시 데이터가 남아있는 부분이 있다면 알려줘.
```

### 받은 코드 실행 및 확인
- 받은 HTML 코드를 `.html` 파일로 저장 후 브라우저로 확인
- 코드 안에 실제 데이터 대신 더미 데이터(`const geojsonData = { ... };`)가 남아있다면:
  - GeoJSON 파일 내용을 복사해 직접 교체하거나
  - AI에게 "이 파일 내용을 코드 안에 넣어줘"라고 재요청
- 지도 범위를 데이터에 맞춰 자동으로 맞추는 `fitBounds()` 적용 여부도 확인

## 3단계 — 필터 기능 추가 (부분 수정 요청)

기존에 완성한 웹지도 파일에 기능을 "추가"하는 작업이므로, 아래 원칙을 반드시 지킨다.

> ⚠️ "여기에 필터 기능 추가해줘"처럼 짧게만 요청하지 않는다. AI가 기존 코드를 참고만 하고 처음부터 새로 작성해버릴 수 있다.

### AI에게 요청하기 (프롬프트 템플릿)

```
역할: 너는 Leaflet 전문 프론트엔드 개발자야.
맥락: (지금 파일 코드 전체 붙여넣기)
요청: 적합도(suitability) 값을 기준으로 필터링하는 슬라이더를 추가해줘.
     기준값 미만인 포인트는 투명하게(opacity 낮춤) 처리해줘.
제약: 기존 코드 구조(getColor, fitBounds 등)는 그대로 유지하고,
     새로 추가/수정한 부분에는 주석을 달아줘.
```

### 결과 확인
1. AI가 새로 만든 HTML 파일 다운로드
2. 더블클릭해 브라우저로 열기
3. 지도 오른쪽 위에 필터 슬라이더가 보이는지 확인
4. 슬라이더를 오른쪽으로 움직여 기준값 미만 포인트가 투명해지는지 확인
5. 슬라이더를 다시 왼쪽 끝으로 이동시켜 모든 포인트가 복원되는지 확인

## 4단계 — GitHub Pages 배포

### 저장소 만들기
1. github.com 로그인 → `+` → New repository
2. Repository name 지정 (예: `프로젝트명-webmap`)
3. **Public** 선택 (무료 Pages는 공개 저장소 필요)
4. Create repository

### 파일 업로드
1. 저장소 페이지에서 "uploading an existing file" 클릭 (또는 `Add file → Upload files`)
2. 웹지도 HTML 파일을 끌어다 놓기
3. 파일명을 반드시 **`index.html`**로 변경
4. `Commit changes` 클릭

### Pages 활성화
1. 저장소 → `Settings → Pages`
2. `Build and deployment → Source: Deploy from a branch`
3. Branch: `main`, 폴더: `/ (root)`
4. `Save`

### 배포 확인
- 1~2분 후 Pages 화면 새로고침 → 초록 박스로 주소 표시
- 주소 형식: `https://[아이디].github.io/[저장소 이름]/`
- 해당 주소로 접속해 지도가 뜨는지 확인

**업로드 전 확인**
- [ ] 올리는 파일이 정제된 웹지도 HTML(핵심 필드만 남긴 버전)인가
- [ ] 원본 CSV·GeoJSON(민감 필드 포함본)을 실수로 같이 올리지 않았는가
- [ ] API 키가 들어간 스크립트를 함께 올린다면, 키를 환경변수로 분리했는가 (`.env` + `.gitignore`)
- [ ] 실수로 키를 올린 적이 있다면 재발급해 기존 키를 무효화했는가

## 5단계 — 반응형 확인 및 사용성 테스트

### 반응형 확인
배포된 주소를 스마트폰 브라우저로 열거나, PC에서 F12 → 디바이스 모드로 확인한다.
- [ ] 지도가 화면에 꽉 차게 나오는가
- [ ] 필터 슬라이더가 화면 밖으로 잘리거나 겹치지 않는가
- [ ] 손가락으로 확대·축소, 드래그가 잘 되는가

### 사용성 테스트
동료·가족 등에게 링크를 열어보게 하고 아래 과업을 준다.

> "이 지도에서 적합도가 가장 높아 보이는 지역 3곳을 찾아 알려주세요."

관찰 포인트: 슬라이더를 스스로 찾아 쓰는지 / 설명 없이도 기능을 이해하는지 / 소요 시간 / 헤매는 지점

## 부록 — AI 코딩 요청 시 체크리스트

**새로 요청할 때**
- [ ] 역할(전문 분야)을 구체적으로 지정했는가
- [ ] 데이터의 맥락(출처·구조·필드 의미)을 설명했는가
- [ ] 요청 사항을 동작 단위로 구체적으로 나열했는가
- [ ] 결과물의 형태(제약: 파일 형태, 라이브러리 로딩 방식 등)를 명시했는가
- [ ] 완성 후 요청 사항을 코드와 대조해 검증하도록 요청했는가

**수정을 요청할 때**
- [ ] "고쳐줘"처럼 짧게만 요청하지 않았는가
- [ ] 기존 코드 전체를 맥락으로 붙여넣었는가
- [ ] "기존 코드 구조는 그대로 유지"라는 유지 조건을 명시했는가
- [ ] 새로 추가/수정한 부분에 주석을 달아달라고 요청했는가
- [ ] 수정 전/후를 비교해 의도치 않은 변경이 없는지 확인했는가

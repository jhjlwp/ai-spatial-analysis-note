프로젝트1(재난 대피소 입지 적합성 분석)이 이미 좌표를 가진 **정형 데이터**(SHP, 행정경계, 위경도 컬럼 등)를 다뤘다면, 프로젝트2는 애초에 지도용으로 만들어지지 않은 **비정형 텍스트 데이터**(뉴스기사, SNS 게시물, 민원 게시판 글 등)에서 위치 정보를 추출해 지도로 옮기는 것을 다룬다. 예: "서울 노원구에서 발생한 침수 피해"라는 문장 속 지명을 뽑아 좌표로 변환(지오코딩)한 뒤 QGIS에 매핑하는 능력이 핵심이다.

## 5차시 — 비정형 데이터 수집 및 지오코딩 (프로젝트2 시작)

### 학습 목표
노원구 관련 뉴스 텍스트를 실제로 수집하고, 문장 속에서 동 이름을 추출한 뒤, 지오코딩(좌표 변환) 준비까지 마친다.

### 1교시 — 복습: 왜 이 작업이 필요한가
지난 3주(프로젝트1)는 이미 좌표가 있는 데이터를 다뤘다면, 이번엔 반대로 좌표가 전혀 없는 순수 텍스트에서 위치를 뽑아낸다. 이 능력이 있으면 지도로 만들어지지 않은 세상의 거의 모든 텍스트 데이터(뉴스, 민원, SNS)를 공간분석 대상으로 바꿀 수 있다.

### 2교시 — 데이터 수집 시도와 방향 전환

**최초 계획 — 네이버 뉴스 검색 API**
민원 데이터는 개인정보 문제로 원문이 대부분 비공개이기 때문에, 실습용으로는 무료이고 가입이 간단한 네이버 뉴스 검색 API가 우선 고려되었다. 절차는 developers.naver.com에서 로그인 후 Application을 등록하고, 사용 API로 "검색"을 선택해 Client ID·Client Secret을 발급받는 방식이다.

**발견된 문제 — 검색 API 신규 발급 중단**
실제 신청 화면에서 "검색 API와 한글인명로마자 변환은 신규 접수를 받지 않으며, 별도의 사업자 제휴가 있는 경우에만 신규 제휴로 산정한다"는 공지가 확인되었다. 즉 개인·학생 개발자는 검색 API를 신규로 발급받을 수 없는 상태이며, 이는 사용자의 설정 오류가 아니라 네이버 측의 정책 변경에 따른 것이다.

**대안 경로 — 구글 뉴스 RSS + 카카오 지오코딩**
- 구글 뉴스 RSS(`https://news.google.com/rss/search?q=검색어&hl=ko&gl=KR&ceid=KR:ko` 형태)는 API 키나 가입 절차 없이 뉴스 제목을 바로 받아올 수 있다.
- 카카오 지오코딩은 developers.kakao.com에서 즉시 셀프 발급되는 REST API 키로 주소→좌표 변환이 가능하다(네이버와 달리 발급이 막혀 있지 않다).

**카카오 REST API 키 발급 절차**
1. developers.kakao.com 로그인 → 내 애플리케이션 → 애플리케이션 추가하기
2. 앱 이름 입력 → 생성
3. 앱 키 → REST API 키 복사

### 3교시 — 수집~지오코딩 파이프라인 구축

**전체 파이프라인**
구글 뉴스 RSS로 "노원구" 검색 → 기사 제목/요약 수집 → 목록 매칭 방식으로 제목에서 노원구 동 이름 추출(정규표현식보다 정확) → 카카오 API로 지오코딩(같은 동은 캐싱해 API 요청 절약) → CSV 저장 → QGIS 매핑

**미션 — AI에게 파이프라인 코드 요청하기**
코드를 직접 처음부터 작성하기 전에, 위 파이프라인을 명확한 프롬프트로 정리해 Claude(또는 사용 중인 AI)에게 요청해본다. 요청이 구체적일수록 AI가 만들어주는 코드도 실습 목적에 정확히 맞는다. 아래 구조를 참고해 팀이 직접 프롬프트를 작성하고, 실제로 AI에게 전달해 코드를 받는다.

```
역할: 너는 공간데이터 파이프라인을 만드는 파이썬 개발자야.
맥락: 구글 뉴스 RSS에서 "노원구" 키워드로 뉴스를 검색하고,
     기사 제목에서 노원구 소속 동 이름을 추출한 뒤,
     카카오 지오코딩 API로 좌표를 변환해서
     QGIS에서 바로 불러올 수 있는 형태로 저장하고 싶어.
요청: 아래 파이프라인을 구현하는 파이썬 스크립트를 작성해줘.
     [1] 뉴스 수집 (구글뉴스 RSS)
     [2] 제목에서 동 이름 추출 (정규표현식보다 정확한 목록 매칭 방식)
     [3] 카카오 지오코딩 (같은 동은 캐싱해서 API 요청 절약)
     [4] CSV로 저장 (QGIS에서 바로 불러올 수 있도록 위도·경도 컬럼 포함)
     [5] Shapefile로도 저장 (좌표계 EPSG:4326 명시)
제약: 카카오 API 키는 스크립트 상단에 변수로 빼서 나중에 쉽게 교체할 수 있게 해줘.
```

> **힌트** — 프롬프트에 "무엇을 입력받아 무엇을 출력해야 하는지"를 파이프라인 단계별로 번호를 매겨 적을수록, AI가 만든 코드를 이해하고 필요할 때 직접 수정하기 쉬워진다. 반대로 "뉴스 지오코딩 스크립트 만들어줘"처럼 뭉뚱그려 요청하면, 원하는 저장 형식(CSV/Shapefile)이나 캐싱 같은 세부사항이 빠질 수 있다.

> **정리** — 아래는 위 프롬프트로 요청했을 때 만들어질 수 있는 코드의 예시다. AI에게 실제로 받는 코드는 세부 구현(변수명, 함수 나누는 방식 등)이 매번 다를 수 있으니, 정답을 맞히듯 비교하기보다 파이프라인의 각 단계([1]~[5])가 코드의 어느 함수에 대응하는지 확인하는 용도로 활용한다.

**실행 방법**
1. 카카오 REST API 키 발급 (2교시 참고)
2. 스크립트 상단의 `KAKAO_API_KEY = "여기에_카카오_REST_API_키_입력"` 부분을 실제 발급받은 키로 교체
3. 터미널에서 실행:
   ```
   pip install feedparser requests pyshp
   python week5_news_geocoding.py
   ```
4. 같은 폴더에 `노원구_뉴스_지오코딩결과.csv`와 `.shp/.dbf/.shx/.prj`가 생성되면 성공

**확인 포인트**: 제목에서 동 이름을 추출하는 단계에서 "지명이 포함된 기사"가 몇 건 나오는지가 중요하다. 뉴스 제목에 동 이름까지 구체적으로 나오는 경우가 생각보다 적을 수 있으며, 그 결과에 따라 검색 전략을 조정해야 할 수 있다.

### 개념 확인 — 메모리에 쌓기 vs 파일에 저장하기
스크립트 실행 중 `results.append(...)`나 `geocoded.append(...)`는 메모리(RAM) 안의 리스트에 데이터를 쌓는 동작일 뿐, 아직 디스크에 파일로 저장된 상태가 아니다. 실제로 파일이 만들어지는 시점은 다음 코드가 실행될 때다.

```python
with open(output_file, "w", newline="", encoding="utf-8-sig") as f:
    writer = csv.DictWriter(f, fieldnames=["title", "dong", "link", "lat", "lon"])
    writer.writeheader()
    writer.writerows(geocoded)
```

`open(output_file, "w", ...)`이 실행되는 순간 비로소 하드디스크에 실제 CSV 파일이 생성되고, `writer.writerows(geocoded)`가 그 안에 실제 데이터 줄을 써넣는다. 이 코드를 만나기 전까지는 `.append()`를 아무리 반복해도 파일은 존재하지 않는다. 스크립트는 다음 순서로 진행된다.

1. 뉴스 수집 결과를 `results` 리스트에 쌓음 (메모리)
2. 지오코딩 결과를 `geocoded` 리스트에 쌓음 (메모리)
3. `writer.writerows(geocoded)` 실행 시점에 비로소 디스크에 파일이 써짐

### 개념 확인 — 필터링 로직
검색된 기사 중 제목에 동 이름이 **있는** 기사만 지오코딩 대상 목록에 포함되고, 동 이름이 **없는** 기사는 목록에서 제외된다(버려진다). 예를 들어 "노원구"로 검색한 50건 중 제목에 동 이름이 들어있는 기사가 2건이라면, 나머지 48건은 목록에 들어가지 않고 살아남은 2건만 지오코딩 대상이 된다.

### 개념 확인 — 임의로 정한 값: 수집 기사 수(max_items=50)
스크립트의 `fetch_news(keyword, max_items=50)`에서 `feed.entries[:max_items]`는 구글 뉴스 서버가 돌려준 전체 기사 목록(보통 100건 안팎) 중 앞에서부터 50개만 잘라 쓰겠다는 의미다. 이 50이라는 숫자는 서버 쪽 제약이 아니라, 지오코딩 API 호출량을 고려해 "적당히 반 정도만 쓰자"는 감으로 임의로 정한 값이다.

이는 프로젝트1의 "500m 격자 간격"과 같은 성격의 문제다 — 엄밀한 근거 없이 정한 값이며, 값을 바꾸면 결과(추출되는 기사 수)도 바뀐다. max_items를 100으로 늘리면 표본이 늘어날 수 있지만(비율이 비슷하다고 가정하면 약 4건 수준으로 추정), "노원구"라는 큰 단위로 검색하는 한 제목에 동 이름이 나오는 비율 자체가 낮다는 근본 문제는 해결되지 않는다. 이 문제의 근본적인 해결책은 동별로 나눠서 검색하는 방법이다.

### 미션 — 표본 늘리기: max_items 조정과 동별 검색
지금까지의 실행은 파이프라인 전체 흐름을 먼저 확인하기 위한 것이었다. 실제 실습에서는 앞서 확인한 두 가지 방법을 학습자가 직접 수행하고 결과를 비교한다.

**① max_items 조정**
`MAX_ITEMS` 값을 50에서 100으로 늘려 다시 실행하고, [2]단계("지명이 포함된 기사" 수)가 몇 건으로 늘어나는지 비교해 기록한다.

**② 동별 검색 확장**
"노원구"라는 큰 단위로만 검색하는 한, 제목에 동 이름이 나오는 비율 자체가 낮다는 근본 문제는 max_items를 아무리 늘려도 해결되지 않는다. `NOWON_DONG_LIST`의 각 동 이름으로 개별 검색을 수행하도록 뉴스 수집 부분을 확장하고, 그 결과를 하나로 합친 뒤 지오코딩한다.

> **힌트** — 동별로 검색하려면 `fetch_news("노원구")`를 한 번만 호출하는 대신, `NOWON_DONG_LIST`를 순회하며 `fetch_news(f"노원구 {동이름}")`처럼 동 이름을 검색어에 포함시켜 여러 번 호출한 뒤 결과를 하나의 리스트로 합치면 된다. 이때 같은 기사가 여러 동 검색에서 중복으로 잡힐 수 있으므로, `link`(기사 URL) 기준으로 중복을 제거하는 과정이 필요하다.

> **정리** — max_items 조정은 표본을 소폭 늘리는 손쉬운 방법이지만, 검색 단위 자체를 동 단위로 좁히는 것이 "제목에 동 이름이 잘 나오지 않는다"는 근본 문제를 해결하는 방법이다. 두 방법을 각각 실행해보고 표본 수 변화를 비교하면, 어떤 개선이 실제로 효과적이었는지 데이터로 확인할 수 있다.

### 참고 스크립트 — `week5_news_geocoding.py`

> 아래 코드는 대화 자료에 있던 실제 작성 과정 기록이 아니라, 지금까지 정리한 파이프라인(뉴스 수집 → 동 이름 추출 → 지오코딩 → 저장) 사양을 그대로 구현한 참고용 스크립트다. QGIS에 바로 불러올 수 있도록 CSV와 Shapefile 두 형식으로 결과를 저장하도록 구성했다.

**구성**

| 함수 | 역할 |
|---|---|
| `fetch_news()` | 구글 뉴스 RSS에서 "노원구" 검색 결과(제목·링크) 수집 |
| `extract_dong()` | 제목에 노원구 소속 동 이름이 있는지 목록 매칭으로 확인, 있으면 반환 |
| `geocode()` | 카카오 지오코딩 API로 동 이름 → 위도·경도 변환, 같은 동은 캐시로 재사용 |
| `save_as_csv()` | 결과를 CSV로 저장 (위도·경도 컬럼 포함, QGIS "구분자로 분리된 텍스트 레이어 추가"로 바로 로드 가능) |
| `save_as_shapefile()` | 결과를 포인트 Shapefile(.shp/.dbf/.shx/.prj, EPSG:4326)로 저장 (QGIS "벡터 레이어 추가"로 바로 로드 가능) |

**전체 코드**
```python
"""
week5_news_geocoding.py

구글 뉴스 RSS에서 "노원구" 관련 기사를 수집하고,
제목에서 노원구 소속 동 이름을 추출한 뒤,
카카오 지오코딩 API로 좌표를 변환해
QGIS에서 바로 불러올 수 있는 CSV와 Shapefile로 저장한다.

파이프라인:
  [1] 뉴스 수집(구글뉴스 RSS)
  [2] 제목에서 동 이름 추출 (목록 매칭 방식)
  [3] 카카오 지오코딩 (같은 동은 캐싱)
  [4] CSV 저장
  [5] Shapefile 저장
"""

import csv
import time

import feedparser
import requests

# ── 설정 ──────────────────────────────────────────────────────
KAKAO_API_KEY = "여기에_카카오_REST_API_키_입력"
SEARCH_KEYWORD = "노원구"
MAX_ITEMS = 50
OUTPUT_CSV = "노원구_뉴스_지오코딩결과.csv"
OUTPUT_SHP = "노원구_뉴스_지오코딩결과.shp"

# 노원구 소속 행정동 목록 (제목 매칭용 — 정식 동명 + 축약 표기 모두 포함)
NOWON_DONG_LIST = [
    "월계1동", "월계2동", "월계3동", "월계동",
    "공릉1동", "공릉2동", "공릉동",
    "하계1동", "하계2동", "하계동",
    "중계본동", "중계1동", "중계4동", "중계2·3동", "중계동",
    "상계1동", "상계2동", "상계3·4동", "상계5동",
    "상계6·7동", "상계8동", "상계9동", "상계10동", "상계동",
]


# ── [1] 뉴스 수집 ────────────────────────────────────────────
def fetch_news(keyword, max_items=MAX_ITEMS):
    """구글 뉴스 RSS에서 기사 목록(제목·링크)을 가져온다."""
    url = f"https://news.google.com/rss/search?q={keyword}&hl=ko&gl=KR&ceid=KR:ko"
    feed = feedparser.parse(url)
    articles = []
    for entry in feed.entries[:max_items]:
        articles.append({"title": entry.title, "link": entry.link})
    return articles


# ── [2] 제목에서 동 이름 추출 ─────────────────────────────────
def extract_dong(title, dong_list=NOWON_DONG_LIST):
    """제목에 노원구 동 이름이 포함되어 있으면 그 동 이름을 반환하고,
    없으면 None을 반환한다 (정규표현식보다 정확한 목록 매칭 방식)."""
    for dong in dong_list:
        if dong in title:
            return dong
    return None


# ── [3] 카카오 지오코딩 ───────────────────────────────────────
def geocode(dong_name, api_key, cache):
    """동 이름을 좌표(위도·경도)로 변환한다. 같은 동은 캐시에서 재사용해
    API 호출 횟수를 줄인다."""
    if dong_name in cache:
        return cache[dong_name]

    url = "https://dapi.kakao.com/v2/local/search/address.json"
    headers = {"Authorization": f"KakaoAK {api_key}"}
    params = {"query": f"서울 노원구 {dong_name}"}

    response = requests.get(url, headers=headers, params=params, timeout=10)
    response.raise_for_status()
    result = response.json()

    if result["documents"]:
        doc = result["documents"][0]
        lat, lon = float(doc["y"]), float(doc["x"])
    else:
        lat, lon = None, None

    cache[dong_name] = (lat, lon)
    time.sleep(0.2)  # API 호출 간격 확보
    return lat, lon


# ── [4] CSV 저장 ─────────────────────────────────────────────
def save_as_csv(records, path):
    """QGIS의 '구분자로 분리된 텍스트 레이어 추가'로 바로 불러올 수 있는
    형태(위도·경도 컬럼 포함)의 CSV로 저장한다."""
    with open(path, "w", newline="", encoding="utf-8-sig") as f:
        writer = csv.DictWriter(f, fieldnames=["title", "dong", "link", "lat", "lon"])
        writer.writeheader()
        writer.writerows(records)


# ── [5] Shapefile 저장 ────────────────────────────────────────
def save_as_shapefile(records, path):
    """geocoded 결과를 포인트 Shapefile(EPSG:4326)로 저장한다.
    QGIS의 '벡터 레이어 추가'로 바로 불러올 수 있다."""
    import shapefile  # pyshp 패키지 (pip install pyshp)

    with shapefile.Writer(path, shapeType=shapefile.POINT) as w:
        w.field("title", "C", size=200)
        w.field("dong", "C", size=20)
        w.field("link", "C", size=200)
        w.field("lat", "F", decimal=6)
        w.field("lon", "F", decimal=6)

        for r in records:
            w.point(r["lon"], r["lat"])
            w.record(r["title"][:200], r["dong"], r["link"][:200], r["lat"], r["lon"])

    # .prj 파일 작성 — 좌표계를 EPSG:4326(WGS84)로 명시해야 QGIS가 정확히 인식한다
    with open(path.replace(".shp", ".prj"), "w") as prj:
        prj.write(
            'GEOGCS["WGS 84",DATUM["WGS_1984",SPHEROID["WGS 84",6378137,298.257223563]],'
            'PRIMEM["Greenwich",0],UNIT["degree",0.0174532925199433]]'
        )


# ── 전체 파이프라인 실행 ──────────────────────────────────────
def main():
    articles = fetch_news(SEARCH_KEYWORD)
    print(f"[1] 뉴스 수집 완료: {len(articles)}건")

    results = []
    for article in articles:
        dong = extract_dong(article["title"])
        if dong:
            results.append({**article, "dong": dong})
    print(f"[2] 지명이 포함된 기사: {len(results)}건")

    geocode_cache = {}
    geocoded = []
    for item in results:
        lat, lon = geocode(item["dong"], KAKAO_API_KEY, geocode_cache)
        if lat is None:
            continue
        geocoded.append({
            "title": item["title"],
            "dong": item["dong"],
            "link": item["link"],
            "lat": lat,
            "lon": lon,
        })
    print(f"[3] 지오코딩 완료: {len(geocoded)}건")

    save_as_csv(geocoded, OUTPUT_CSV)
    print(f"[4] CSV 저장 완료: {OUTPUT_CSV}")

    save_as_shapefile(geocoded, OUTPUT_SHP)
    print(f"[5] Shapefile 저장 완료: {OUTPUT_SHP}")


if __name__ == "__main__":
    main()
```

### 4교시 — QGIS에서 불러오기
- CSV: `레이어 → 레이어 추가 → 구분자로 분리된 텍스트 레이어 추가` → X필드=`lon`, Y필드=`lat`, 좌표계 EPSG:4326 지정
- Shapefile: `레이어 → 레이어 추가 → 벡터 레이어 추가` → `.shp` 파일 선택 (좌표계는 `.prj`에 이미 지정되어 있어 별도 지정 불필요)

## 6차시 — 공간 조인 및 주제도 제작

### 학습 목표
① 5차시에서 만든 뉴스 포인트를 행정동에 공간조인해서 "어느 동 뉴스인지" 속성을 붙이고, ② 이미 가진 인구밀도 데이터로 분류기법을 비교하며 코로플레스맵을 만든다.

### 1교시 — 개념 복습
- **속성조인**: 공통 컬럼(예: 코드)으로 표 두 개를 합치는 것
- **공간조인**: 위치 관계("이 점이 이 폴리곤 안에 있는가")로 합치는 것 — 오늘 사용할 방식

### 2교시 — 공간조인 실습
5차시에서 만든 `노원구_뉴스_지오코딩결과.csv`를 QGIS에 아직 불러오지 않았다면 먼저 불러온다 (5차시 4교시에서 안내한 방법 그대로: `구분자로 분리된 텍스트 레이어 추가`, X필드=`lon`, Y필드=`lat`, 좌표계 EPSG:4326).

그다음 GUI로 공간조인을 진행한다.
1. `Processing → Toolbox` 열기 (또는 상단 검색창에 "join attributes by location" 검색)
2. `Join attributes by location` 실행
3. Input layer: 뉴스 포인트 레이어
4. Join layer: `노원구(행정경계)`
5. Predicate: intersects
6. Run

결과 속성테이블을 열어서, 각 뉴스 포인트에 어느 동(행정동 이름 필드)이 붙었는지 확인한다. 붙는 뉴스 포인트 수는 5차시에서 실제로 지오코딩에 성공한 기사 수에 따라 팀마다 달라질 수 있으므로, 정해진 개수를 기대하기보다 각 포인트가 올바른 동에 매칭됐는지를 확인하는 데 집중한다.

### 3교시 — 주제도 제작: 분류기법 비교
이번엔 뉴스 데이터가 아니라 프로젝트1에서 이미 가진 `노원구(행정경계)`의 `pop` 필드로 진행한다 — 데이터가 충분해서 분류기법 차이를 눈으로 확인하기 좋다.

1. `노원구(행정경계)` 레이어 더블클릭 → Symbology
2. 렌더링 방식: Graduated
3. Value: `pop`
4. 먼저 **Equal Interval(등간격)**로 5단계 설정 → 지도가 어떻게 보이는지 확인(스크린샷 남겨두기)
5. 같은 방식으로 **Quantile(분위수)**로 바꿔서 확인
6. 마지막으로 **Natural Breaks(Jenks)**로 바꿔서 확인

세 지도의 색 분포가 어떻게 달라지는지가 오늘의 핵심 관찰 포인트다.

## 7차시 — 지도 스토리텔링 및 최종 디자인

### 학습 목표
6차시까지 만든 결과물(공간조인된 뉴스 지도 + 분류기법 비교 주제도)을 하나의 완성된 이야기로 묶어, 발표 가능한 최종 산출물로 만든다.

### 1교시 — 개념 복습
- **One Map One Message**: 지도 하나에는 메시지 하나만 담는다.
- **스토리텔링 3단 구조**: 문제제기 → 분석과정 → 시사점

### 2교시 — 우리 프로젝트의 스토리 정하기
지금까지 만든 두 결과물(뉴스 지명 분포, 인구밀도 분류기법 비교 주제도)을 하나의 흐름으로 묶는 예시가 제시된다.

- **문제제기**: "노원구 뉴스는 어디를 얼마나 다루고 있을까?"
- **분석**: 뉴스 지명 분포 + 인구밀도 분류기법 비교
- **시사점**: "인구가 많은 동일수록 뉴스에도 더 많이 언급되는가?" 같은 질문 제기

표본 수가 적을 경우(실제 수는 5차시 지오코딩 결과에 따라 팀마다 다를 수 있음) 정량적 결론보다는 "한계와 향후 확장 방향"을 제시하는 쪽이 정직하다는 점이 강조된다. 표본이 적다는 것을 인정하고 가는 것 자체가, 프로젝트1 3차시에서 다룬 "결과 검증" 원칙을 실천하는 사례로 언급된다.

### 3교시 — AI로 해설문 초안 만들어보기
AI에게 요청할 때 아래와 같은 구조(역할·맥락·요청·제약)를 사용하는 예시가 제시된다.

```
역할: 너는 데이터 저널리스트야.
맥락: 노원구 뉴스(표본 수는 팀마다 다름)의 위치를 지도화하고, 행정동별 인구밀도를
      3가지 분류기법(등간격/분위수/자연분류)으로 비교한 주제도를 만들었어.
요청: 이 지도들을 하나의 스토리로 묶는 제목 3개 후보와,
      지도 아래 들어갈 2~3문장 해설 문구를 작성해줘.
제약: 표본 수가 적다면 그 한계를 솔직히 인정하는 톤으로, 과장 없이 써줘.
```

### 4교시 — 최종 산출물 정리
1. QGIS 프린트 레이아웃으로 최종 지도 완성 — 4차시(프로젝트1)에서 만든 `week4_map_layout.py` 코드를 재활용해, 뉴스 레이어 + 인구 레이어 구성으로 바꿔 적용
2. GitHub/Notion 포트폴리오에 프로젝트2 결과물 업로드

**최종 지도 스크립트 실행 전 확인 사항**
스크립트 상단의 레이어 이름 변수 2곳을 QGIS 왼쪽 패널의 실제 레이어 이름과 정확히 맞춰야 한다.

```python
LAYER_DONG = "노원구(행정경계)"
LAYER_NEWS = "노원구_뉴스_지오코딩결과"   # 6차시 공간조인 결과 레이어명이 다르면 수정
```

`LAYER_NEWS`는 6차시에 `Join attributes by location`을 실행한 뒤 QGIS가 자동으로 붙인 이름(예: "Joined layer")일 수 있으므로, 왼쪽 패널에서 실제 이름을 확인해 맞춰야 한다.

**스크립트가 하는 일**
- 행정동 레이어에 자연분류(Jenks) 5단계 인구밀도 코로플레스맵 적용
- 뉴스 포인트를 빨간 별 마커로 강조
- 제목 + "표본 수 한계 명시" 부제 + 범례 + 축척바 + 방위표를 갖춘 A4 가로 레이아웃 생성
- PDF 자동 저장

부제에 표본 한계를 미리 넣어두는 것은, 4차시(프로젝트1)에서 배운 "결과의 한계를 솔직히 밝히는" 습관을 발표 자료에 그대로 반영한 것이다.

## 8차시 — 중간 점검: 포트폴리오 리뷰

이 차시는 실습보다 점검·정리가 중심이다.

### 1) 포트폴리오 체크리스트 자가진단

| 항목 | 확인 |
|---|---|
| 문제정의가 명확한가 | 프로젝트1: 재난 대피소 입지 / 프로젝트2: 노원구 뉴스 지명 분포 |

| 결과 시각화가 효과적인가 | 최종 PDF 지도가 완성되어 있는가 |
| 결론이 데이터에 근거하는가 | 산지 문제(MAUP)·표본 수 한계를 숨기지 않고 명시했는가 |

### 2) GitHub 저장소 정리
아래는 GitHub을 처음 써보는 학습자도 따라할 수 있도록 계정 생성부터 업로드까지 순서대로 정리한 절차다. 저장소에 올릴 스크립트 파일명은 차시나 팀마다 다를 수 있으므로, 정해진 이름을 그대로 쓰기보다 실제로 작업한 파일명을 사용한다.

**GitHub이란?**
GitHub은 코드와 문서 파일을 온라인에 저장하고 다른 사람과 공유할 수 있는 서비스다. 이번 실습에서는 지금까지 작성한 스크립트와 결과물을 한곳에 모아, 포트폴리오로 공개하는 용도로 사용한다.

알아두면 도움이 되는 용어는 다음과 같다.

| 용어 | 의미 |
|---|---|
| 저장소 (Repository) | 파일들을 모아두는 프로젝트 단위 폴더. 이 안에 스크립트와 PDF 지도를 담는다 |
| 커밋 (Commit) | 저장소에 파일 추가·수정 등의 변경사항을 확정해서 남기는 것. "저장하기"와 비슷한 개념이다 |
| README | 저장소를 처음 보는 사람에게 "이 프로젝트가 무엇인지" 설명하는 파일. 저장소 메인 화면에 자동으로 표시된다 |
| Public / Private | 저장소를 다른 사람도 볼 수 있게 공개(Public)할지, 본인만 볼 수 있게 비공개(Private)로 둘지 정하는 설정 |

이 실습에서는 Git 명령어(커맨드라인)를 몰라도, 웹 브라우저 화면만으로 계정 생성부터 파일 업로드까지 모두 진행할 수 있다.

**① GitHub 계정 만들기 (이미 계정이 있다면 건너뛴다)**
1. 웹 브라우저에서 `github.com` 접속
2. 우측 상단 `Sign up` 클릭
3. 이메일 주소, 비밀번호, 사용자명(username)을 순서대로 입력해 계정 생성
4. 가입 시 입력한 이메일로 온 인증 메일을 열어 인증 완료

**② 새 저장소(repository) 만들기**
1. 로그인한 상태에서 우측 상단 `+` 아이콘 클릭 → `New repository` 선택
2. `Repository name`에 저장소 이름 입력 (예: `nowon-spatial-analysis`처럼 프로젝트 내용을 알 수 있는 이름 권장)
3. `Public`(공개) / `Private`(비공개) 중 선택 — 포트폴리오로 공개할 목적이면 `Public` 권장
4. `Add a README file` 항목에 체크
5. 하단 `Create repository` 버튼 클릭

**③ 스크립트·결과 파일 업로드 (Git 명령어 없이 웹 화면만으로 가능)**
1. 방금 만든 저장소 페이지에서 `Add file` 버튼 → `Upload files` 클릭
2. 지금까지 각 차시에서 작성한 스크립트 파일(.py)들을 화면으로 끌어다 놓거나, `choose your files`로 직접 선택해 첨부한다. 파일명은 실제로 작업한 이름을 그대로 사용한다.
3. 완성한 PDF 지도 파일들도 같은 방식으로 함께 업로드한다.
4. 화면 하단으로 스크롤 → `Commit changes` 버튼 클릭 → 업로드 완료

**④ README 작성**
1. 저장소 메인 화면에서 `README.md` 파일을 클릭
2. 파일 우측 상단의 연필 모양 아이콘(Edit) 클릭
3. 프로젝트 목적, 사용한 데이터, 주요 결과, 확인된 한계를 3~5줄로 간단히 요약해 작성한다
4. 우측 상단 `Commit changes` 버튼 클릭 → 저장

# 과제 제시문: 상가업소 데이터 검색·시각화 웹앱 개발

## 배경

소상공인시장진흥공단은 전국 상가업소에 대한 정보를 담은
**`소상공인시장진흥공단_상가(상권)정보`** 데이터셋을 공공데이터포털(data.go.kr)을 통해
무료로 제공하고 있습니다. 이 데이터는 영업 중인 전국 상가업소의 상호명, 업종코드,
업종명, 지번주소, 도로명주소, 경도·위도 등을 담고 있으며 분기 단위로 갱신됩니다.
상권 분석, 창업 입지 선정, 지역 경제 연구 등 다양한 분야에서 활용되는 자료입니다.

이번 과제에서는 이 공공데이터를 활용하여, **사용자가 원하는 상호명을 검색하면
해당 매장들의 위치를 지도 위에 시각화해주는 웹 애플리케이션**을 직접 설계하고
구현합니다.

## 과제 목표

사용자가 상가업소 CSV 파일을 웹 화면에 업로드하고, 검색창에 상호명을 입력하면:

1. 해당 문자열을 포함하는 상호명의 데이터만 추출하고
2. 추출된 데이터를 지도 위에 마커로 표시하며
3. 검색된 결과만 별도 파일로 저장할 수 있는

하나의 완결된 웹 프로그램을 만드는 것이 목표입니다.

## 데이터

- 공공데이터포털에서 **`소상공인시장진흥공단_상가(상권)정보`** 데이터셋을 내려받아
  사용합니다. (전국 단위 또는 특정 시도 단위로 파일이 나뉘어 제공됩니다.)
- 주요 컬럼: `상호명`, `지점명`, `상권업종대분류명`, `도로명`, `도로명주소`,
  `경도`, `위도` 등
- 이 데이터에는 **각 상가업소의 좌표(경도·위도)가 이미 포함**되어 있습니다.
  즉 주소를 좌표로 변환하는 지오코딩 과정을 별도로 수행할 필요가 없습니다 —
  이미 제공된 좌표를 그대로 읽어서 지도에 표시하면 됩니다.

## 기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 데이터 입력 | 사용자가 CSV 파일을 웹 화면에서 직접 선택(또는 드래그앤드롭)해서 불러올 수 있어야 한다 |
| 검증 | 업로드한 CSV에 필요한 컬럼(상호명/지점명/도로명/경도/위도)이 없으면 사용자에게 알려야 한다 |
| 검색 | 검색창에 문자열을 입력하면 `상호명`에 해당 문자열이 포함된 행만 걸러낸다 (부분 일치) |
| 지도 표출 | 기본 배경지도(베이스맵) 위에 검색된 매장들을 마커로 표시하고, 마커 클릭 시 상호명·지점명·도로명을 보여준다 |
| 화면 이동 | 검색 결과에 맞춰 지도 범위가 자동으로 조정되어야 한다 |
| 결과 저장 | 검색된 데이터만 GeoJSON 또는 CSV 형식의 별도 파일로 저장할 수 있어야 한다 |
| 결과 없음 처리 | 검색 결과가 0건일 때 적절한 안내 문구를 보여줘야 한다 |

## 구현 조건

- 서버 없이 **브라우저에서 모든 처리가 이루어지는 정적 웹페이지**로 구현한다
  (HTML/CSS/JavaScript).
- 지도는 오픈소스 라이브러리(예: [Leaflet](https://leafletjs.com/))와
  공개 베이스맵([OpenStreetMap](https://www.openstreetmap.org/) 등)을 활용한다.
- CSV 파싱은 직접 구현하거나 공개 라이브러리(예: [PapaParse](https://www.papaparse.com/))를
  사용할 수 있다.
- 업로드한 CSV 파일이 서버로 전송되지 않고, 전적으로 사용자 브라우저 안에서만
  처리되어야 한다.

## 생각해볼 점 (설계 시 고려사항)

1. CSV 파일 용량이 수십 MB에 달할 수 있습니다. 전체 데이터를 한 번에 메모리에
   올려 처리하는 방식과, 필요한 부분만 나누어 처리하는 방식의 차이를 고민해보세요.
2. 좌표 값이 비어있거나 숫자로 변환되지 않는 행은 어떻게 처리해야 할까요?
3. OpenStreetMap 타일 서버는 **타일 사용 정책(Tile Usage Policy)**에 따라
   유효한 `Referer` 헤더가 없는 요청을 차단할 수 있습니다. 브라우저에서
   로컬 HTML 파일을 `file://` 경로로 직접 열었을 때는 `Referer`가 전송되지
   않아 지도가 차단될 수 있는 반면, 웹서버(GitHub Pages 등)로 `https://`
   배포하면 정상적으로 `Referer`가 전송되어 문제가 사라집니다. 이 차이를
   직접 확인하고 이유를 설명할 수 있어야 합니다.
4. 검색 결과를 CSV로 저장할 때 한글이 깨지지 않으려면 어떤 처리가
   필요한지 고려해보세요(예: UTF-8 BOM 추가 등 엑셀 호환성 문제).

## 제출물

- 완성된 웹페이지 소스 코드 (단일 HTML 파일 또는 파일 묶음)
- GitHub Pages 등으로 배포한 접속 URL (선택)
- 간단한 사용 설명서(README) — 어떤 데이터를 썼고, 어떻게 실행·배포하는지 포함

## 평가 기준

| 항목 | 배점 비중 |
|---|---|
| 요구 기능이 모두 정상 작동하는가 | 높음 |
| 대용량 CSV를 처리할 때 성능 문제가 없는가 | 중간 |
| 예외 상황(잘못된 파일, 결과 없음, 좌표 결측 등) 처리가 되어 있는가 | 중간 |
| 코드 구조와 가독성 | 중간 |
| UI/UX의 완성도 | 낮음~중간 |

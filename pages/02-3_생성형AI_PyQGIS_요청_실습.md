이 실습의 목표는 다음과 같다.

2. AI가 생성한 코드를 그대로 실행하지 않고, 실행 전후로 검증하는 절차를 익힌다.

| ③ 단위 분할 | 큰 작업을 검증 가능한 작은 단위로 나누어 요청하는 능력 | 3장 |

# 1장 — 기초: 생성형 AI의 한계와 이 실습의 범위

## 1.1 생성형 AI의 한계

생성형 AI는 QGIS 코드를 매우 빠르게 작성해 준다. 그러나 이 능력에는 분명한 한계가 있으며, 이 한계를 이해하지 못한 상태로 사용하면 오히려 시간을 더 쓰게 된다.

- **AI는 사용자의 화면을 보지 못한다.** 어떤 레이어가 열려 있는지, 필드명이 무엇인지, 좌표계가 무엇인지는 사용자가 직접 알려주지 않으면 AI가 알 수 없다.
- **AI는 QGIS 버전을 확정할 수 없다.** Processing 알고리즘의 ID나 파라미터 이름은 QGIS 버전에 따라 달라질 수 있다. 이 때문에 AI가 실제로는 존재하지 않거나 이름이 바뀐 알고리즘 ID를 자신 있게 제시하는 경우가 있다.
- **AI가 만든 코드는 초안이다.** 문법적으로는 올바르게 보여도, 실제 환경에서 실행했을 때 오류가 나거나 의도와 다른 결과를 낼 수 있다.

따라서 이 실습의 핵심은 "AI에게 코드를 받아내는 기술"이 아니라, **AI에게 정확한 정보를 제공하고, 받은 코드를 검증하는 절차**이다.

## 1.2 이 실습에서 다루는 범위

이 실습은 노원구 재난대피소 입지적합성 분석(2차시 QGIS 실습)의 각 단계를 대상으로 한다.

- 좌표계 통일
- 분석 격자 생성
- 인구밀도 산출 및 격자 조인
- 기존 대피소·도로까지의 거리 계산
- 정규화 및 가중합
- 시각화

각 단계마다 다음 순서로 연습한다: **① 프롬프트 작성 → ② AI 응답 검증 → ③ 실제 실행 및 결과 확인.**

## 1.3 확인 사항

- [ ] 생성형 AI가 QGIS 화면이나 데이터를 직접 볼 수 없다는 점을 설명할 수 있다
- [ ] AI가 존재하지 않는 알고리즘 ID나 파라미터를 제시할 수 있다는 점을 인지하였다
- [ ] 이 실습에서 다룰 6개 분석 단계를 확인하였다

# 2장 — 핵심 개념: 좋은 프롬프트의 구성 요소

## 2.1 프롬프트에 포함해야 할 네 가지 요소

PyQGIS 코드를 요청하는 프롬프트는 다음 네 가지 요소를 포함해야 한다. 하나라도 빠지면 AI가 그 부분을 임의로 가정하여 채우는데, 이 가정이 실제 환경과 다르면 코드가 실행되지 않는다.

| 요소 | 설명 | 노원구 분석에서의 예 |
|---|---|---|
| 목표 | 무엇을 만들고 싶은지 | "행정동 경계 전체를 덮는 사각형 격자를 생성하고 싶다" |
| 맥락 | 사용 중인 레이어 이름·필드명·좌표계·실행 환경 | "레이어 이름은 `boundary_layer`, 좌표계는 EPSG:5179, QGIS Python 콘솔에서 실행" |
| 제약조건 | 사용하고 싶은 방식이나 피해야 할 방식 | "Processing 알고리즘을 사용하고 싶다", "결과는 메모리 레이어로만 생성한다" |
| 검증 기준 | 결과가 맞는지 어떻게 확인할 것인지 | "생성된 격자 개수와 격자 하나의 크기를 출력하는 코드도 함께 요청" |

## 2.2 나쁜 프롬프트와 좋은 프롬프트 비교

**나쁜 프롬프트의 예**

> "노원구 대피소 분석 파이썬 코드 짜줘"

이 프롬프트에는 목표(격자를 만드는 것인지, 거리를 계산하는 것인지)도, 맥락(레이어 이름, 좌표계)도 없다. AI는 이 정보를 임의로 채워 넣을 수밖에 없으므로, 결과 코드를 그대로 실행하면 대부분 오류가 발생한다.

**좋은 프롬프트의 예**

> "QGIS Python 콘솔에서 실행할 코드가 필요하다. 이미 불러온 레이어는 다음과 같다: 행정동 경계(`boundary_layer`), 좌표계는 EPSG:5179. 이 경계 전체를 덮는 500m 간격의 사각형 격자를 Processing 알고리즘으로 생성하고, 결과를 메모리 레이어로 만들어 지도에 추가하는 코드를 작성해 달라. 사용한 알고리즘 ID도 함께 알려 달라."

이 프롬프트는 목표·맥락·제약조건을 모두 포함하고 있으며, 마지막 문장(알고리즘 ID 요청)은 다음 절에서 다룰 **검증 절차**를 위한 준비이기도 하다.

## 2.3 확인 사항

- [ ] 프롬프트에 포함해야 할 네 가지 요소를 설명할 수 있다
- [ ] 나쁜 프롬프트를 좋은 프롬프트로 직접 고쳐 써 보았다

# 3장 — 실습: 단계별로 프롬프트 작성하고 코드 검증하기

이 장에서는 노원구 분석의 각 단계를 실제로 진행한다. 각 절은 **미션 → 먼저 해보기 → 프롬프트 예시 → 검증** 순서로 구성된다. "먼저 해보기" 단계에서는 아래 예시를 보지 않은 상태로 프롬프트를 직접 작성하여 텍스트 파일(예: `3-1_prompt.txt`)로 저장한 뒤에만 예시를 확인한다. 이후 검증 단계에서는 직접 작성한 프롬프트로도 실제로 AI에게 코드를 요청해 실행해 보고, 예시 프롬프트로 만든 코드와 어떤 차이(사용된 알고리즘, 오류 발생 여부, 결과값)가 있는지 비교한다.

## 3.1 좌표계 통일 요청하기

**미션:** 행정동 경계·대피소·도로 세 레이어의 좌표계를 EPSG:5179로 통일하는 코드를 AI에게 요청하는 프롬프트를 작성한다.

**먼저 해보기:** 아래 프롬프트 예시를 보지 않은 상태로, 위 미션을 해결할 프롬프트를 직접 작성하여 `3-1_prompt.txt` 파일로 저장한다. 저장을 마친 뒤에만 아래 예시를 확인한다.

**프롬프트 예시**

> "QGIS Python 콘솔에서 실행할 코드가 필요하다. 현재 불러온 레이어는 `dong_layer`, `shelter_layer`, `road_layer` 세 개이며, 각각 좌표계가 다를 수 있다. 세 레이어 모두 EPSG:5179로 재투영한 새 레이어를 만들고, 원래 좌표계와 변환 후 좌표계를 함께 출력하는 코드를 작성해 달라."

**검증 체크리스트**

- [ ] 사용된 Processing 알고리즘 ID를 `processing.algorithmHelp()`로 직접 확인하였다
- [ ] 코드 실행 후 출력된 좌표계가 실제로 EPSG:5179인지 확인하였다
- [ ] 원본 레이어가 그대로 유지되었는지, 의도치 않게 덮어써지지는 않았는지 확인하였다
- [ ] 직접 작성한 프롬프트로도 코드를 요청해 실행해 보고, 예시로 만든 코드와의 차이를 비교하였다

## 3.2 격자 생성 요청하기

**미션:** 행정동 경계 전체를 덮는 격자를 생성하는 프롬프트를 작성한다. 격자 간격은 500m로 한다.

**먼저 해보기:** 아래 프롬프트 예시를 보지 않은 상태로, 위 미션을 해결할 프롬프트를 직접 작성하여 `3-2_prompt.txt` 파일로 저장한다. 저장을 마친 뒤에만 아래 예시를 확인한다.

**프롬프트 예시**

> "QGIS Python 콘솔 환경이다. `dong_layer_5179`(좌표계 EPSG:5179)의 전체 범위를 덮는 500m 간격의 사각형 격자를 Processing 알고리즘으로 생성하고, 행정동 경계 밖으로 벗어나는 격자는 잘라내는 코드까지 작성해 달라. 사용한 알고리즘 ID 두 개(격자 생성, 자르기)를 코드 주석으로 명시해 달라."

**검증 체크리스트**

- [ ] 응답에 포함된 두 알고리즘 ID가 실제로 존재하는지 `QgsApplication.processingRegistry().algorithms()`로 검색해 확인하였다
- [ ] 파라미터 이름(`HSPACING`, `EXTENT` 등)이 `algorithmHelp()` 결과와 일치하는지 확인하였다
- [ ] 실행 후 격자 개수(`featureCount()`)가 상식적인 범위인지 확인하였다 (예: 노원구 면적을 500m 격자로 나눈 대략적인 개수와 비교)
- [ ] 직접 작성한 프롬프트로도 코드를 요청해 실행해 보고, 예시로 만든 코드와의 차이(알고리즘 선택, 격자 개수 등)를 비교하였다

## 3.3 인구밀도 산출 및 조인 요청하기

**미션:** 행정동 인구를 면적으로 나누어 인구밀도를 계산하고, 이를 격자에 결합하는 프롬프트를 작성한다.

**먼저 해보기:** 아래 프롬프트 예시를 보지 않은 상태로, 위 미션을 해결할 프롬프트를 직접 작성하여 `3-3_prompt.txt` 파일로 저장한다. 저장을 마친 뒤에만 아래 예시를 확인한다.

**프롬프트 예시**

> "`dong_layer_5179`에는 `인구수`라는 필드가 있다. 이 레이어에 `인구밀도` 필드를 추가하여 `인구수 / 면적`으로 계산하고 싶다. 면적은 QGIS의 `$area` 함수 대신 Python 코드에서 지오메트리 객체로 직접 계산해 달라. 이후 격자 레이어(`grid_layer`)의 각 격자 중심점이 속한 행정동의 `인구밀도` 값을 격자에 결합하는 코드도 함께 작성해 달라."

**검증 체크리스트**

- [ ] `인구밀도` 값이 0이나 음수, 비정상적으로 큰 값이 아닌지 몇 개 피처를 직접 출력하여 확인하였다
- [ ] 조인 이후 격자 개수가 조인 이전과 같은지 확인하였다 (조인 방식에 따라 일부 격자가 누락될 수 있다)
- [ ] AI가 제시한 조인 방식이 "격자 중심점 기준"인지 실제 코드를 읽고 확인하였다 (AI가 다른 기준으로 조인하는 코드를 제시할 수 있다)
- [ ] 직접 작성한 프롬프트로도 코드를 요청해 실행해 보고, 예시로 만든 코드와의 차이(조인 방식, 누락된 격자 수 등)를 비교하였다

## 3.4 거리 계산 요청하기 (대피소·도로)

**미션:** 각 격자 중심점에서 가장 가까운 기존 대피소까지의 거리와, 가장 가까운 도로까지의 거리를 계산하는 프롬프트를 작성한다.

**먼저 해보기:** 아래 프롬프트 예시를 보지 않은 상태로, 위 미션을 해결할 프롬프트를 직접 작성하여 `3-4_prompt.txt` 파일로 저장한다. 저장을 마친 뒤에만 아래 예시를 확인한다.

**프롬프트 예시**

> "격자 레이어(`grid_layer`)의 각 격자 중심점에서, 대피소 레이어(`shelter_layer`)까지의 최단 거리를 미터 단위로 계산하여 `대피소거리` 필드에 저장하는 코드가 필요하다. Processing 알고리즘을 사용하고 싶다. 사용할 알고리즘의 정확한 ID를 모른다면, 후보가 될 수 있는 알고리즘 ID 목록을 `processingRegistry()`로 검색하는 코드부터 먼저 작성해 달라."

이 단계는 AI가 알고리즘 이름을 정확히 기억하지 못할 가능성이 특히 높은 지점이다. 위 프롬프트의 마지막 문장처럼 **AI에게 먼저 후보를 검색하게 하고, 그 결과를 사용자가 확인한 뒤 다음 요청을 이어가는 방식**이 한 번에 완성된 코드를 요구하는 것보다 안전하다.

**검증 체크리스트**

- [ ] AI가 제시한 알고리즘 ID가 검색 결과 목록에 실제로 존재하는지 확인하였다
- [ ] 존재하지 않는다면, 검색된 후보 목록을 AI에게 다시 알려주고 그중에서 선택하도록 요청하였다
- [ ] 계산된 거리 값 중 최솟값·최댓값이 상식적인 범위인지 확인하였다 (예: 최솟값이 0에 가깝고, 최댓값이 노원구 크기를 넘지 않는지)
- [ ] 직접 작성한 프롬프트로도 코드를 요청해 실행해 보고, 예시로 만든 코드와의 차이(선택된 알고리즘, 거리값 등)를 비교하였다

도로까지의 거리도 동일한 절차로 요청하고 검증한다.

## 3.5 정규화·가중합 요청하기

**미션:** 세 필드(인구밀도, 대피소거리, 도로거리)를 정규화하고, 방향을 맞춘 뒤 가중합하여 `적합도점수`를 계산하는 프롬프트를 작성한다.

**먼저 해보기:** 아래 프롬프트 예시를 보지 않은 상태로, 위 미션을 해결할 프롬프트를 직접 작성하여 `3-5_prompt.txt` 파일로 저장한다. 저장을 마친 뒤에만 아래 예시를 확인한다.

**프롬프트 예시**

> "`grid_layer`에는 `인구밀도`, `대피소거리`, `도로거리` 세 필드가 있다. 각각을 min-max 정규화하여 0~1 값으로 만들고 싶다. 단, `도로거리`는 값이 작을수록 좋은 지표이므로 정규화 후 `1 - 정규화값`으로 반전해야 한다. 세 정규화값에 각각 0.4, 0.3, 0.3 가중치를 곱해 합산한 `적합도점수` 필드를 추가하는 코드를 작성해 달라."

이 단계에서는 방향을 반대로 처리하는 실수가 발생하기 쉬우므로, 어떤 필드가 반전되었는지 특히 주의 깊게 확인한다.

**검증 체크리스트**

- [ ] 어떤 필드가 반전(`1 - 정규화값`)되었는지 코드에서 직접 확인하였다
- [ ] `적합도점수`의 최솟값·최댓값이 0~1 사이인지 확인하였다
- [ ] 가중치 합이 1이 되는지(0.4+0.3+0.3) 코드와 별개로 직접 계산하여 확인하였다
- [ ] 직접 작성한 프롬프트로도 코드를 요청해 실행해 보고, 예시로 만든 코드와의 차이(반전 처리 여부, 점수 분포 등)를 비교하였다

## 3.6 시각화 요청하기

**미션:** `적합도점수`를 기준으로 5단계 자연 구간(Jenks) 분류의 단계 구분 지도를 만드는 프롬프트를 작성한다.

**먼저 해보기:** 아래 프롬프트 예시를 보지 않은 상태로, 위 미션을 해결할 프롬프트를 직접 작성하여 `3-6_prompt.txt` 파일로 저장한다. 저장을 마친 뒤에만 아래 예시를 확인한다.

**프롬프트 예시**

> "`grid_layer`의 `적합도점수` 필드를 기준으로, 자연 구간(Jenks) 분류 방식의 5단계 단계 구분(Graduated) 스타일을 적용하는 코드가 필요하다. 색상은 적합도가 높을수록 진해지는 단일 색상 계열로 해 달라."

**검증 체크리스트**

- [ ] 실제 지도 화면에서 5단계로 구분되어 표시되는지 확인하였다
- [ ] 적합도가 높을수록 색이 진해지는 방향으로 스타일이 적용되었는지 육안으로 확인하였다
- [ ] 직접 작성한 프롬프트로도 코드를 요청해 실행해 보고, 예시로 만든 코드와의 차이(분류 방식, 단계 수 등)를 비교하였다

## 3.7 확인 사항

- [ ] 6개 단계 모두에서 예시를 보기 전에 프롬프트를 텍스트 파일로 먼저 작성하였다
- [ ] 작성한 프롬프트를 예시와 비교하여 빠진 요소(목표·맥락·제약조건·검증 기준)가 없는지 확인하였다
- [ ] 직접 작성한 프롬프트로 만든 코드와 예시 프롬프트로 만든 코드를 최소 한 단계 이상에서 실제로 실행하여 비교하였다
- [ ] 각 단계에서 최소 한 가지 이상의 검증 항목을 실제로 확인하였다
- [ ] AI가 존재하지 않는 알고리즘 ID나 파라미터를 제시한 경험이 있다면 어떤 상황이었는지 기록하였다

# 4장 — 응용: 오류 대응과 반복 개선

이 장에서는 AI의 응답이 틀렸거나 코드가 오류를 냈을 때, 대화를 이어가며 문제를 해결하는 방법을 다룬다.

## 4.1 오류 메시지를 그대로 전달하기

코드 실행 중 오류가 발생하면, 오류 메시지를 요약하지 말고 **QGIS 콘솔에 출력된 전체 오류 메시지(Traceback 포함)를 그대로** AI에게 전달한다. 오류 메시지의 마지막 줄만 전달하면 원인 파악에 필요한 정보가 부족할 수 있다.

**프롬프트 예시**

> "방금 준 코드를 실행했더니 다음 오류가 발생했다: (전체 오류 메시지 붙여넣기). 이 오류의 원인이 무엇인지, 그리고 어떻게 수정해야 하는지 알려 달라."

## 4.2 AI가 잘못된 알고리즘 ID·파라미터를 제시한 경우

3.4절에서 다룬 것처럼, AI가 제시한 알고리즘 ID나 파라미터 이름이 실제로는 존재하지 않는 경우가 있다. 이 경우 다음 순서로 대응한다.

1. `QgsApplication.processingRegistry().algorithms()`로 실제 존재하는 알고리즘 목록을 검색한다.
2. 검색된 후보 목록(ID와 이름)을 그대로 AI에게 전달하며 다시 질문한다.
3. AI가 후보 중 하나를 선택하면, `processing.algorithmHelp()`로 파라미터를 직접 확인한 뒤에만 코드를 실행한다.

**프롬프트 예시**

> "방금 알려준 알고리즘 ID로 검색했더니 존재하지 않는다는 오류가 났다. 대신 다음 목록에서 실제로 등록된 알고리즘을 찾았다: (검색 결과 붙여넣기). 이 중 내가 원하는 작업(격자 중심점에서 가장 가까운 지점까지의 거리 계산)에 맞는 알고리즘이 무엇인지 알려 달라."

## 4.3 반복 실행 가능한 함수로 확장 요청하기

3장에서 검증을 마친 코드가 준비되면, 이를 하나의 함수로 묶어 격자 간격이나 가중치를 바꾸어가며 반복 실행하도록 요청할 수 있다. 이는 [PyQGIS 입문 교과서] 4장에서 다룬 내용과 이어진다.

**프롬프트 예시**

> "지금까지 검증한 코드(격자 생성 → 조인 → 거리 계산 → 정규화 → 가중합)를 하나의 함수로 묶고 싶다. 함수의 인자로 격자 간격과 세 가중치를 받아, 결과 레이어를 반환하도록 만들어 달라. 기존에 검증된 알고리즘 ID와 파라미터는 그대로 유지해 달라."

이처럼 이미 검증한 코드를 재료로 제시하면, AI가 새로운 알고리즘 ID를 임의로 추가하는 것을 줄일 수 있다.

## 4.4 확인 사항

- [ ] 오류 메시지를 요약하지 않고 전체를 전달하는 방식을 연습하였다
- [ ] AI가 제시한 알고리즘 ID를 직접 검색하여 존재 여부를 확인하고, 틀렸을 경우 후보 목록을 다시 전달하며 대화를 이어갔다
- [ ] 검증된 코드를 함수로 묶어 반복 실행하도록 요청하였다
